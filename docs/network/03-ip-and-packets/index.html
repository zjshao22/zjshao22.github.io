用 IP 数据报、路由器和排队解释逐跳转发与分组交换

第三节：数据怎样穿过校园网

你在宿舍打开课程平台，或用手机流量查看一段国内视频。设备与服务端通常没有一根专用直连线；中间可能经过不同网络。IP 的工作是让数据报朝目标网络位置前进。 这节课不需要知道真实运营商的内部拓扑，只用一个简化网络学习转发原理。

一、什么是 IP 数据报

应用交给网络的内容不会单独“裸奔”。IP 把上层交来的数据放在负载里，在前面加上首部，形成 IP 数据报。首部包含源 IP 地址、目标 IP 地址等控制信息；目标地址是路由器决定下一步的重要依据。

IP 地址用于描述网络中的位置，不是人的姓名，也不是课件路径。比如宿舍设备可能拿到一个校内使用的地址；访问外部服务时还可能经过地址转换或代理。为了练习，下面只用 A、B 这样的代号表示目的地，不把教学代号当成真实校园网地址。

二、路由器只决定“下一跳”

设想 A 是宿舍笔记本，B 是课程平台服务器；R1、R2、R3 是路由器。R1 不必预先知道从 A 到 B 的每一段连接，只需依据自己的转发表决定交给哪一个相邻设备。下一台路由器再做同样的事。

数据报写着目标 B
路由器 R1
查表，交给 R2
路由器 R2
查表，交给 B
课程平台 B
接收数据报

先看一张只用于课堂推演的简化表：

路由器目标 B 的下一跳目标 C 的下一跳
R1R2R3
R2BR3
R3R2C

目标是 B，且数据报已经到 R1：R1 查表交给 R2，R2 查表交给 B。若目标换成 C，R1 交给 R3，R3 交给 C。现实中的路由器通常按地址前缀匹配转发表，而不是直接用 B、C 两个字母；表格只为练习“本地决定下一跳”。

如果 R1 到 R2 的连接坏了，不能仅凭这张旧表说“一定会自动绕开”。网络需要获知故障并有新的可用转发信息。多条可能路径不等于每次故障都能无缝恢复。

三、为什么把数据分成包

宿舍里有人下载大文件，旁边有人只发一条班级群消息。如果下载者长期独占整条链路，短消息也得等到下载完成。分组交换让数据被拆成可独立处理的包，不同通信的包可以交替使用同一条链路。路由器逐份处理，当前出口忙时，后来到达的包可能先排队。

用一个具体队列推演：出口正在发送 A1，等待队列最多放两份；B1、A2 已在排队。这时 B2 到来，队列已满，B2 可能被丢弃。接收端看到的顺序与发送端原本的动作不一定相同，沿途排队或走不同路径都可能造成差异。

分组交换提高了链路共享的灵活性，但并不承诺“无等待、无丢包”。网络繁忙时，排队使响应变慢；缓冲区放不下时，包可能丢失。这也解释了为什么“视频转圈”可以与“设备已经连上 Wi-Fi”同时发生：接入成功只是一个环节，后续的服务和网络状态仍可能影响体验。这里不能仅凭转圈就断定具体是哪一段出了问题。

四、IP 的承诺有多大

IP 提供尽力而为的数据报服务：网络会尝试把每份数据报送向目标，但协议本身不保证它一定到达、不重复、按顺序到达，或在某个时限内到达。IP 转发也不要求先为一组数据报建立一条专用电路，所以称为无连接。

“不可靠”在这里是严格的技术用语，意思是IP 不作交付保证，不是说校园网平时一定坏。需要完整、按序内容的应用可以借助 TCP 等上层机制检测丢失并重传；对实时性的取舍可能不同。IP 负责尽力转发，是否补救由上层服务与应用决定。

五、读懂 IPv4 首部中影响转发的字段

IPv4 首部的基础长度是 20 字节；若带选项会更长。它包含源地址、目标地址、总长度、协议号、标识与分片相关字段、首部校验和等。目标地址用于转发查找；协议号告诉目标主机负载应交给哪类上层协议，例如 TCP 对应 6、UDP 对应 17。普通目的地址转发通常不靠 TCP 端口。

生存时间 TTL 是另一项关键字段。每经过一台普通 IPv4 转发路由器，TTL 至少减 1；减到 0 时，路由器丢弃数据报，通常会发送相应的 ICMP 错误信息。这样可以限制错误路由形成的循环。假设发出时 TTL 为 4，经过 R1、R2、R3 后分别变成 3、2、1；再经过 R4 时会到 0，不能继续正常转发。实际 ICMP 可能被网络策略过滤，收不到错误报告不等于没有丢包。

IPv4 的总长度计入 IP 首部与 IP 负载，不计外层链路帧的首部与尾部。若总长度为 1040 字节、IP 首部为 20 字节，则 IP 负载为 1020 字节。该负载可能是 TCP 段，但“IP 负载长度”不直接等于“应用正文长度”，因为 TCP 自己也有首部。

六、链路速率、传播与排队分别影响什么

一条链路发送长度为 L 位的包，链路速率为 R 位/秒，仅将各位推入链路所需的发送时延约为 L/R。传播时延与信号经过的距离及介质中的传播速度有关；路由器还可能产生处理与排队时延。这些量不能合成一个含糊的“网速”。

例如，一个 1500 字节的帧在 100 Mb/s 链路上的发送时延约为 1500 × 8 ÷ 100,000,000 = 0.00012 秒，即 0.12 毫秒。这只算发送，不包括传播、排队、协议开销和应用处理。若同样大小的帧进入 10 Mb/s 出口，发送时延约为1.2 毫秒。出口长期收到的流量若接近或超过其处理能力，排队时间会增大，缓存满后可能丢包。

多台设备串联也不意味着端到端时间简单等于“链路条数 × 文件大小 ÷ 最慢速率”：不同包可以形成流水线，传播与排队会改变结果。做题时先说清楚包长、速率、是否排队、是否考虑传播，再计算。

练习与解析

题 1：一个 IPv4 数据报总长度为 1500 字节，IP 首部 20 字节，TCP 首部 20 字节，且没有其他位于 TCP 负载中的协议开销。最多有多少字节 TCP 负载？

题 2：一个 1000 字节的包通过 20 Mb/s 出口，仅计算发送时延是多少？

查看两题解析

题 1：1460 字节。 先扣 IP 首部得到 1480，再扣 TCP 首部得到 1460。

题 2：0.4 毫秒。 1000 × 8 ÷ 20,000,000 = 0.0004 秒。这个数不能直接称为整次网页访问的延迟。

推演任务：在纸上运行一个出口队列

出口速率为 8 Mb/s，每份包计入发送时间的长度均为 1000 字节，不另计开销。一次只发一份，发送开始后不中断；等待队列按到达先后处理，最多放 2 份等待的包，正在发送的包不占等待位置。队列满时，新到的包直接丢弃。忽略传播与处理时延。

  1. 先用 L/R 算出发完一份包需要几毫秒。
  2. 在每个到达时刻写出“正在发送谁、等待队列有哪些包、是否丢弃新包”。
  3. 继续画到队列清空，标出每份成功发送的包的起止时刻，并算出 B1 从到达到开始发送的等待时间。

结果应包含一张时间线、被丢弃的包和等待时间。检查依据是等待位置是否已满，以及前一份包是否已经发完，不能只看链路是否连通。

查看迁移题参考答案

每份包改为发送 0.5 毫秒：A1 在 0～0.5 发送，B1 在 0.5～1 发送，A2 在 1～1.5 发送，B2 在 1.5～2 发送。0.6 毫秒时 B1 已开始发送，只有 A2 在等待，所以 B2 还能进入第二个位置，本次没有被丢弃。
