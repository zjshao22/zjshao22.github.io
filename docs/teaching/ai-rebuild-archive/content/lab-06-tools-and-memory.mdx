# L6｜受限工具、记忆与代码修复

对应 28—31、36 单元。三项任务使用不同状态：工具改变沙盒观察，记忆改变外部 JSON，代码修复改变学生目录源码。动作的提出、执行和完成核验分别记录。

## 任务一：读两个整数并求和

```sh
python3 -B ai_lab.py l6 --output ./runs/l6 --seed 42
```

程序训练三个动作的 softmax 策略，然后实际读取沙盒 `numbers.txt`、计算 12+7、给出结束动作。动作类型由学得权重选择，文件名、状态文字和数字解析由显式控制程序给出。它是狭窄策略，不能冒称通用大模型自主行动。

教师先给固定工作流作基线，再让学生追踪每步的状态、概率、动作参数、执行结果与预算。程序还检查参数错误、越权路径、文件大小和终止；这些是对执行器的直接挑战，不代表证明模型抵御所有提示注入。

通用本地模型选配分支让真实语言模型选择同一动作集合。无效 JSON 或越权动作应留下原始调用和错误后停止，不用窄策略兜底伪装成功。

## 任务二：跨任务读回更正记忆

```sh
python3 -B practice.py memory --output ./runs/memory --seed 42
```

在新目录中，程序先保存截止日和地点，更新地点，再尝试用旧版本改日期。旧写入遭拒后，程序重读最新、合并日期并读回，最终两项变更都保留。后续任务从真实 JSON 读取截止日并附来源；模型参数没有更新。

学生检查 `memory-store.json` 和 `memory.json` 的版本、来源、旧值与当前值。实验使用单写入者；版本比对加原子替换不构成多进程事务。重复运行换输出目录，不能删除前次日志后声称原记录从未发生。

## 任务三：在副本修复平均值程序

包内 `data/coding` 提供 `average.py`、`test_average.py` 与教师参考实现。先把整个 coding 目录复制到自己的独立工作目录，在副本运行：

```sh
python3 -B -m unittest -v test_average.py
```

基线故意有错：小数被截断、负数不正确、空列表除零。先保存失败输出，再只修改副本中的 `average.py`，直到契约测试通过；参考文件在独立尝试后再看。契约限定数值列表，未要求支持字符串等任意输入。

教师安排需求分析与只读审查并行，由一人整合写入；学生保存基线、差异、前后测试和分工依赖。多人一致意见不能替代真实测试，串行和并行的比较也需计入协调成本。

## 学生任务与验收

提交三组真实产物，解释工具成功断言、记忆版本冲突和代码修复覆盖范围；至少提供一个拒绝、一次失败恢复和一个个人独立变式。

## 独立变式

教师另给一个未公开数值列表或一条新的正式记忆更正。学生先预测、再运行，并保存错误定位。代码测试通过不能提升为完整编程代理能力；纸面分工也不能声称测得了真实大模型并行加速。
