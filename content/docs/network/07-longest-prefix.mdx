# 第七节：路由器怎样选择下一跳

你在宿舍访问课程平台时，路由器读到目标 IPv4 地址，需要决定从哪个出口发送。它的转发表可能同时有“去整个校园网”的大范围规则和“去某栋楼网段”的小范围规则。一个简单想法是**按表格从上往下找，找到第一条包含目标的记录就停**。先试试看：这个办法能让大范围规则与某栋楼的特殊出口同时发挥作用吗？

## 一、一条转发表记录包含什么

一条简化的记录有两部分：**目标地址块（前缀）** 和**下一跳或出口**。路由器先判断目标 IP 是否落在记录指定的地址块里，再按选中的记录转发。实际设备还会受路由类型、策略等影响；这里先学习普通 IPv4 转发中最基本的匹配规则。

下面是为练习编的校园网络转发表，不对应任何真实学校：

| 目标前缀         | 交给哪个出口 | 覆盖范围                   |
| ---------------- | ------------ | -------------------------- |
| 0.0.0.0/0        | 出口 A       | 所有 IPv4 地址，即默认路由 |
| 192.168.0.0/16   | 出口 B       | 192.168 开头的地址         |
| 192.168.10.0/24  | 出口 C       | 192.168.10 开头的地址      |
| 192.168.10.32/27 | 出口 D       | 最后一组为 32～63 的地址   |

**默认路由 /0**不固定任何地址位，所以能匹配所有 IPv4 地址。它常用来处理“表里没有更具体路线”的目标。默认路由并不是保证这条路径一定可达；它只说明路由器选择了哪个出口。

先预测：对 **192.168.10.34** 与 **192.168.10.80** 使用“第一条匹配就停”，会各选哪个出口？若改成“前三组相同就走同一出口”，能否保留 .32～.63 这段地址的特殊出口？

<details>
<summary>核对朴素办法会在哪里失败</summary>

第一行 /0 包含所有 IPv4 地址，两次都会选 A，后面的 B、C、D 永远没有机会。只看前三组则无法区分 .34 与 .80，可是 .34 位于 D 对应的 .32～.63 范围，.80 不在。我们需要一个既能使用大范围规则、又能保留局部例外的比较办法。

</details>

改进办法是：**先保留所有匹配记录，再选择其中前缀最长的一条**。更具体的规则在自己覆盖的范围内优先，其他目标仍可使用大范围规则。这就是最长前缀匹配。

## 二、一步一步查找 192.168.10.34

这个目标同时属于四条记录：它属于所有 IPv4 地址；前两组是 192.168；前三组是 192.168.10；最后一组 34 也落在 32～63。因此四条规则都匹配。

比较前缀长度：/0、/16、/24、/27。**/27 固定的位最多，范围最具体**，所以交给**出口 D**。这不是“选最先写在表上的规则”，也不是“选出口名字最大的规则”。

| ------------- | ----------------------------------- | -------- |
| 192.168.10.80 | /16、/24；不在 32～63，故不匹配 /27 | C        |
| 192.168.20.4  | /16；第三组不是 10                  | B        |

## 四、把最长前缀匹配写成可执行的判断

对表中每条前缀，先判断**目标地址按该前缀长度保留的位**是否与前缀相同；把所有匹配记录留下，再选前缀长度最大的记录。对前缀 192.168.10.32/27，最后一组的掩码是 224，即二进制 11100000。目标末组 34 的二进制是 00100010，与 11100000 按位与得到 00100000，即 32，所以 .34 匹配该 /27。目标末组 80 与同一掩码按位与得到 64，故不匹配。

这样计算比“前三组一样就归同一路”严谨，尤其是 /27、/21 等不在点分十进制边界的前缀。表的书写顺序并不决定结果。现实实现可能使用专门的数据结构高效查找，但计算结果应与这个定义一致。

### 更具体路由与汇总路由

大范围前缀可以把多个相邻地址块概括成一条路由，减少需要通告的记录。例如 **192.168.10.0/24**可概括 .0/25 和 .128/25 两个连续块。然而汇总路由只表达地址范围，**不保证这个范围内每个目标实际可达**。若某个更具体的网段要从另一出口走，可以再放一条更长前缀，使它覆盖汇总路由在该范围的转发选择。

假设从原表删去 **192.168.10.32/27**，目的 .34 就选择 /24 的出口 C；把 /27 加回来后才改选 D。这个变化体现了转发表的**更具体例外**，并不表示数据报自身的目标地址发生变化。

## 五、匹配结果之外还要知道什么

若连默认路由都没有，且没有任何前缀匹配，设备通常无法按这张表继续转发，可能丢弃数据报并在条件允许时报告错误。若路由系统给同一个前缀学到多条候选路由，会先经过路由协议、管理距离、度量值或策略等过程选择可安装的转发表记录；**最长前缀匹配**针对已安装的转发表做目的地址查找，不等于全部路由选择机制。

## 六、转发与“最后一跳”之间还缺一步

选中了出口并不等于可以直接把数据报扔给空气。在下一节采用的**以太网逻辑链路模型**中，若下一跳与路由器在同一本地链路上，还要知道**下一跳的链路层地址**，才能构造当前这段链路的帧。Wi-Fi 无线帧另有接收者等地址字段，不能直接套用以太网帧的地址格式。下一节将回答：已知道下一跳的 IPv4 地址，怎样找到它在本地链路上的地址？

## 七、动手推演：逐条匹配，排除“最长但不匹配”

下面的转发表有意不按前缀长短排列；每个前缀只对应一个出口，且没有额外策略。

| 目标前缀         | 出口 |
| ---------------- | ---- |
| 192.168.10.96/28 | F    |
| 0.0.0.0/0        | A    |
| 192.168.10.32/27 | D    |
| 192.168.0.0/16   | B    |
| 192.168.10.0/24  | C    |

在纸上为 **192.168.10.34、192.168.10.80、192.168.10.100、203.0.113.8** 各画一行，五条记录各画一列。先写出 /27 与 /28 的地址范围，再逐格标记“匹配”或“不匹配”，最后在匹配项中圈出最长前缀。**交出这张匹配矩阵和每个目标的出口**。验证时调换表格行序重新判断，结果应不变；同时检查“选中的前缀确实包含目标”以及“没有更长的匹配项”。

<details>
<summary>第一步提示：暂时不看出口</summary>

先只判断目标是否落在每条前缀覆盖的范围里。/27 留 5 位，/28 留 4 位；用块起点加块大小减 1 求终点。

</details>

<details>
<summary>第二步提示：只比较留下的记录</summary>

把不匹配的格子划掉，再比较剩余记录的前缀长度。表中有 /28，并不说明每个目标都能选它；“出口 F”这个名字也不参与比较。

</details>

<details>
<summary>完成后核对匹配矩阵</summary>

/27 的 .32 块覆盖 .32～.63；/28 的 .96 块覆盖 .96～.111。下表的“是”表示匹配；各列沿用题目中的表格顺序。

| 目标           | .96/28 → F | /0 → A | .32/27 → D | /16 → B | /24 → C | 最终出口 |
| -------------- | ---------- | ------ | ---------- | ------- | ------- | -------- |
| 192.168.10.34  | 否         | 是     | 是         | 是      | 是      | D（/27） |
| 192.168.10.80  | 否         | 是     | 否         | 是      | 是      | C（/24） |
| 192.168.10.100 | 是         | 是     | 否         | 是      | 是      | F（/28） |
| 203.0.113.8    | 否         | 是     | 否         | 否      | 否      | A（/0）  |

.34 的最长匹配是 /27，尽管整张表里还有更长的 /28，它却不在 .96～.111 内，不能选 F。.80 也不能选 F。最长前缀匹配先要求“匹配”，再比较“最长”；表中第一条或全表最长的记录都不自动获胜。

</details>
