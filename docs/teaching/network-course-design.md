# 计算机网络：课程设计与 AI 制作规则

修订日期：2026-10-14。本文供教师与后续维护课程的 AI 使用，不进入学生页面。

## 本轮判断与调整范围

现有八节适合作为“从 Web 访问理解网络原理”的入门单元。校园课程平台主线、四层职责、封装图示、IP 尽力而为、字节序、CIDR、最长前缀匹配与 ARP 的顺序成立，保留主体内容。

需要调整的是学习活动与检验方式：原有文字题常把答案直接放在题后，真实观察步骤不够具体，换条件后的独立练习较少。此次补充观察记录、纸笔推演和迁移题，将文字参考解析折叠；实验放在相关知识处，学生不需要先学编程或安装网络模拟器。另将学生首页中的审查编号、教材与资料依据、完整课程规划移到教师文档。

当前没有计算机网络课程的正式学时、考试题库或培养方案，不据其他课程的 64 学时安排推断本课要求。八节仍是入门单元；若需承担完整大学课程，必须另安排传输、路由、应用、安全等内容，不能把现有八节改名后视为已经覆盖。

2026-10-14 已对照本次要求、实际课程文件与相关教学方法记录整理上述规则。历史材料中的特定实验设置不自动成为本课制度；实际授课条件和学习结果仍按本课证据记录。

## 从问题推导机制的教学主线

| 节  | 具体问题与可先尝试的办法                           | 失败情形或不足                                             | 引出的机制与验证                                             |
| --- | -------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------ |
| 01  | 把字节送到对方，是否就完成了课件请求？             | 到了错误资源，或接收方不知道消息边界，仍不能得到正确课件。 | 应用协议约定消息含义与边界；对照资源、状态和内容记录。       |
| 02  | 让浏览器自己处理每种链路与沿途设备，是否可行？     | 换链路就要改应用，职责纠缠，故障也难定位。                 | 分层服务与对等协议；用同一访问中的标识与端点表检查职责。     |
| 03  | 给一个文件长期独占链路，能否照顾其他通信？         | 小消息要等大文件结束；共享后又会有排队与满队列。           | 分组交换与尽力而为；运行给定 FIFO 队列、计算发送与等待时间。 |
| 04  | 只发正文，或给整份文件只加一次首部，是否足够？     | 逐跳转发与端点交付需要控制信息，多段数据又各有开销。       | 分层封装、分段与每跳换帧；逐段账单检查层次与长度。           |
| 05  | 直接使用各自机器的整数表示，能否一致解码？         | 同样两个字节被读成不同数；字段宽度或位置不一致也会失败。   | 协议规定布局与字节序；逐字段解码并改变一个字段的排列规则。   |
| 06  | 只看地址前三组，就能决定网段与容量吗？             | /26、/27 的边界会被忽略；网关和固定设备也占地址。          | CIDR 与掩码；核对块起点、可分配数量及扩容后是否重叠。        |
| 07  | 取第一条匹配，或取整表最长的一条，会怎样？         | 表格顺序可能改变结果；更长的前缀可能根本不匹配目标。       | 先列全部匹配再选最长；用边界地址、无匹配和删除路由验证。     |
| 08  | 已知远端 IP，直接查远端 MAC 或一直查网关，可以吗？ | ARP 范围在本地；本地目标与跨网段目标的下一跳不同。         | 先路由后地址解析、复用有效缓存；核对 ARP 与数据帧时序。      |

先让学生尝试解释或预测，再读页面中对应原理。保留已有合理讲解；这张表用于教师发问，不要求每节机械重复同一套栏目。

## 主教材

确立 **Computer Networks: A Systems Approach** 为主教材，作者 **Larry Peterson、Bruce Davie**。使用第六版章节体系的官方开放版，来源为 [Systems Approach 官方仓库](https://github.com/SystemsApproach/book) 与 [在线版本](https://book.systemsapproach.org/)。官方 [LICENSE](https://github.com/SystemsApproach/book/blob/master/LICENSE) 标明 CC BY 4.0；源文件公开，满足英文与开放资源偏好。

选它的理由是：从应用需求解释网络架构，能保持当前 Web 场景的起点；对分层、封装、性能、IP、子网与 ARP 有完整讲解；后续传输、拥塞、路由、应用和安全也可沿同一教材继续。教材是教师组织原理与核验内容的依据，学生不会被要求跳到英文书中补齐页面缺失的讲解。

官方开放内容持续更新，与商业印刷版不保证同步。2026-10-14 核验时，源仓库 VERSION 为 `6.2-dev`；本课称“第六版体系的官方开放版”，不称最新商业第六版全文。之后每轮改版记录取材日期与具体源文件；需要统一整学期阅读版本时，记录所采用的官方仓库提交或标签。

## 一节课怎样开展

不把网页中的“节”直接等同于固定一课时；根据学生基础与实际课时拆分。每节围绕一个能够回答的问题开展：

1. **先判断。** 给学生看情境或记录，先提出自己的办法，写出预测与理由。教师据此知道哪些概念需要补充。
2. **推导再讲原理。** 用上表的失败情形追问朴素方案，再使用现有图示与例题，把机制、术语、职责和假设讲清；复杂情形只在会影响本题判断时引入。
3. **当场做。** 到对应知识处完成观察或纸笔任务，保留字段、表格、中间计算与解释。提供的教学记录让没有操作条件的学生也能练习。
4. **核对并订正。** 先完成题面再展开解析。教师追问错误来自单位、字段、前缀边界、推理步骤还是假设。
5. **改变条件。** 独立完成迁移题。修改关键条件，例如缓存是否命中、子网前缀是否改变、某条路由是否删除，而不只换一个数字。

| 节  | 当场可检查的成果                     | 教师追问                                                |
| --- | ------------------------------------ | ------------------------------------------------------- |
| 01  | 请求路径、类型、状态及观察结论       | 哪一项记录支持你的判断？主体成功能否代表全部资源成功？  |
| 02  | 标识与职责对应表、故障排查起点       | 这是直接观察到的，还是需要进一步验证的解释？            |
| 03  | 队列/发送过程与时延计算              | 位和字节是否换算？发送时延能否代替整次访问延迟？        |
| 04  | 分段、数据报与帧的长度表             | 当前计数口径属于哪层？哪些开销被假设排除？              |
| 05  | 按字段布局得到的数值与字节           | 为什么这些字节属于这个字段？排列方向是否正确？          |
| 06  | 不重叠的子网方案与设备容量           | 网关是否占用可分配地址？网络/广播地址有没有分配给设备？ |
| 07  | 逐条匹配表与最终出口                 | 更长的前缀是否实际匹配目标？删掉它后结果如何变化？      |
| 08  | 最终 IP、下一跳 IP、帧目标与缓存判断 | 缺的是谁的链路地址？缓存命中后还需要这次查询吗？        |

验收看学生是否能给出过程、理由和边界。会选正确选项只是一个信号，不能替代学生解释。给定记录的分析属于推演成果，不能写成学生本人实际抓包或实际配置的证据。

学生卡住时采用三级提示：先指向应检查的条件或字段，再给一个中间步骤，最后才对照完整解析。例如最长前缀任务先问“.80 在 .32～.63 内吗”，再提示列出所有匹配，最后核对出口。记录提示使用情况；展开答案后重做算订正，不算首次独立完成。

下一次课用一道短题检查延迟保持：不看上一页，解释一个机制为什么需要出现，或完成一条新的字段/路由判断。隔一段时间再用陌生情境检验迁移。依据实际回答补概念，不根据浏览过几页推断掌握。

## 可接续的课堂记录

教师在现有 Markdown 记录中保存最小检查点即可；无需新增数据库、登录系统或学生 AI 服务。AI 根据教师实际提供的课堂记录整理，不自行推定学生表现，也不将学生个人信息写入公开仓库。

```text
日期与章节：
本次已讲解的机制：
学生独立完成的任务及可核对依据：
使用提示/展开答案后完成的任务：
发现的误解与已讲解的纠正：
当场验证、延迟保持待验证、陌生迁移待验证：
下次从哪页、哪道题或哪个问题继续：
需要补的前置知识与下一项动作：
```

项目源码与课程文件以本仓库为准。外部接续记录只需保存项目入口、重要决定与简要状态；详细学生材料留在教师适当管理的位置。共享记录遵循读最新内容后合并、一次一个写入者、写后读回核验的约定，不把本地修改说成云端已经同步。

## AI 参与课程制作的具体工作流

| 环节           | AI 应完成的工作                                                  | 保留的核验依据                                             |
| -------------- | ---------------------------------------------------------------- | ---------------------------------------------------------- |
| 明确任务       | 读取现有规则、章节与原题；列出学生起点、已有概念、目标与范围缺口 | 规则来源和待定假设，不把推测写成既定约定。                 |
| 查证取材       | 用主教材组织概念，用官方协议/工具文档核验细节                    | 来源链接、取材日期与影响教学的模型假设。                   |
| 制作内容       | 在原页面中完善定义、示例、图示、操作任务、答案与迁移题           | 学生能只凭页面完成任务；不用厂商真实内部拓扑作虚构背书。   |
| 独立审读       | 另一次审读或另一个 AI 检查事实、题面、答案、先修依赖与前后矛盾   | 可定位的问题及修正理由；不以两次 AI 答案相同当作事实证明。 |
| 核算与技术验证 | 独立重算长度、时延、子网与匹配；构建 MDX；浏览页面和逐屏演示     | 算式/小程序结果、构建输出及实际页面检查。                  |
| 课堂后维护     | 汇总学生在哪一步答错，增补必要解释、反例或前置练习               | 学生表现对应到概念或步骤，修订记录说明为什么改。           |

每次交给 AI 的任务至少包含：要修改的文件、学生已经学过什么、可用条件、必须保留的内容、要解决的问题、可验收的成果。约束可直接写成以下工作包：

```text
在现有计算机网络章节上修改，先判断原模式是否合理。
先读取当前协作要求、课程设计与实际源文件；区分已确认、历史材料与候选建议。
保持校园课程平台主线，学生页面只呈现定义、讲解、图示和操作练习。
学生没有另一本讲义，不假定编程基础、管理员权限或额外软件。
按具体问题、朴素方案、失败情形、机制改进、推演或观察组织；先让学生预测，卡住时分层提示。
用主教材组织概念，遇到协议边界时用官方来源核验。
将实验放在对应知识处，题面给足数据、假设与操作步骤。
参考答案可展开自检，增加改变关键条件的独立迁移题。
分别核对题面、答案、计算、图示、页面链接与放映效果。
教师规则、教材、取材链接和待定假设写入 docs/teaching。
交付时说明改了什么、为何改、验证结果及实际尚未覆盖的范围。
保存接续点；已制作不等于已授课，已讲解不等于学生已经掌握。
```
