# 18｜推理时怎样花更多计算

同一个模型多想几步或多生成几次，是否必然更准确？增加计算可能让系统发现更好路径，也可能重复同一误解。必须定义预算、候选的相关性和选择器的可靠性，才能判断“多算”是否有用。

## 固定权重也能改变求解过程

最简单的直接回答只生成一次；多候选方法在不同随机路径下生成多份答案，再投票或验证；搜索把中间状态组织成树，选择可扩展节点；工具把部分计算交给确定程序。这些都可以在参数固定时完成。它们改变的是推断过程，不等于重新训练。

教学任务是凑数：从 2、3、4 中每个数恰用一次，只用二元加、减、乘、除与括号得到 14；不允许拼接数字、额外常数或阶乘。候选 `2+3×4` 正确，`(2+3)×4` 得 20，`2×3+4` 得 10。一个只看字符串长度的选择器没有保证；算术解析器可以验证数值与用数规则。如果允许偷偷使用额外数字，即使结果为 14 也不合格。

## 计算收益有条件

若每次独立候选成功率为 $p$，生成 $n$ 次至少一份正确的概率为 $1-(1-p)^n$。例如 $p=0.3,n=4$ 时为 0.7599。但这只是“至少存在正确候选”，并非最终选择成功率；候选也未必独立。如果四次都沿同一错误路径，收益可能很小；如果验证器错选，正确候选仍会丢失。

| 系统步骤   | 可能收益               | 仍需检查                   |
| ---------- | ---------------------- | -------------------------- |
| 多候选采样 | 探索不同路线           | 是否真的多样、预算是否一致 |
| 多数投票   | 抵消部分偶然错误       | 共同错误能否占多数         |
| 程序验证   | 筛去违反明确规则的候选 | 验证器覆盖与漏洞           |
| 树搜索     | 在中间状态回退与扩展   | 状态表示、启发式与终止     |
| 调用工具   | 利用精确计算或外部信息 | 参数、权限、工具错误       |

串行长轨迹与并行短候选的总词元可能相同，延迟却不同。若需要逐步依赖，不能把所有步骤随意并行。测量时同时记录生成词元、模型调用数、验证次数、总耗时和最终成功率，避免只用“思考时间”一个模糊量。

## 从盲搜到有检查的搜索

穷举所有算式可作为小任务基线：状态包含已用数字、当前表达式与剩余资源；动作是合法扩展；终止条件是规则满足且结果等于目标，或预算耗尽。启发式可优先接近目标的状态，但“当前数值接近”不保证最终可达，需要反例检验。

搜索器是系统控制，不等于模型本身。模型可提出候选或评估中间状态，验证器提供不同性质的证据。为了公平比较，保留确定穷举、固定规则和模型辅助三个版本，分别报告搜索量和错误来源。

## 测试时计算与测试时学习

“多生成一次”通常不改参数；“把本轮结果当训练信号执行优化”则涉及测试时学习。外部写记忆文件又是第三种变化。区分方式是检查权重、优化器、上下文和外部状态的实际变化，而不是看产品是否用了“学习”一词。若用多数答案作伪监督更新，可能把共同错误强化，不能认为无标签适应天然可靠。

教师在 [L3](/ai-labs/README.md) 中让学生先冻结策略，比较直接候选与验证选择，再单独进行训练，保存两套状态。学生每次运行前写预算和成功标准，运行后检查候选存在率与最终成功率的差别。

## 学生任务：预算公平吗

A 系统生成 1 条 100 词元轨迹，B 生成 5 条各 20 词元，再各运行一次验证。两者“计算一样”是否成立？如果单次正确概率为 0.5，4 次候选至少一次正确的理想概率是多少？

理想至少一份正确的概率为 0.9375；最终选择成功还依赖验证器。相同生成词元只是一个预算口径，不能据此断言墙钟时间或算力完全相同。验收要求预先固定主预算，并完整报告额外开销。
