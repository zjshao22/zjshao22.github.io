# 31｜编程、界面操作与多智能体

让 AI 修改程序，关键不是它写了多少行，而是修改是否满足契约、是否影响其他行为、能否重复验证。让多个代理同时工作，还要解决依赖、通信和共享状态。并行不是免费收益，文件冲突也不能靠“大家更聪明”自动消失。

## 先给一个可检验的修复任务

以下函数要返回非空数列平均值；空列表返回 `None`，不允许除零异常：

```python
def average(values):
    return sum(values) // len(values)
```

朴素代理可能只把 `//` 换成 `/`，修复小数截断，却仍在空列表失败。更完整的过程是先读契约与现状，建立测试 `[1,2]→1.5`、`[-2,-1]→-1.5`、`[]→None`，再修改，运行新旧相关测试，检查差异。测试通过表示这些范围内行为成立，不证明所有类型输入都受支持；是否支持字符串或 NaN 需要另定契约。

## 代码执行与界面动作都依赖观察

代码代理通过文件、测试输出和错误信息了解环境；界面代理通过截图、可访问性信息与当前页面状态了解环境。按钮位置会变化，旧截图上的坐标不一定仍有效。一个可靠循环是观察当前状态、选择动作、执行、重新观察，再判断目标是否达成。点击成功不等于表单提交成功，测试进程启动也不等于测试全部通过。

课程只在独立小目录和模拟界面进行任务，不修改真实账号或外部系统。修改前保存基线，动作后检查差异；若失败，说明哪些状态已改变以及如何回滚，不能删除失败轨迹后只保留最后成功截图。

## 多智能体先画依赖，再谈加速

任务 A“读需求并列测试”耗时 3 单位，B“检查已有实现”耗时 3，C“合并方案并修改”耗时 2，且 C 依赖 A、B。理想串行延迟为 8，并行 A/B 后再 C 为 5；总工作仍为 8。若通信与合并多耗 1，延迟变成 6。若两位代理都直接改同一文件，冲突与覆盖可能使结果更慢、更差。

| 子任务             | 可并行性         | 写入约定           |
| ------------------ | ---------------- | ------------------ |
| 分析需求、设计反例 | 相互独立，可并行 | 只读后汇报         |
| 检查测试输出       | 依赖实际运行     | 不编造未运行结果   |
| 修改公共文件       | 存在共享状态     | 同一时刻单写入者   |
| 集成与最终验证     | 依赖全部修改     | 读最新、合并、读回 |

多个代理可能共享同一基础模型和训练偏差，所以一致意见不等于独立证据。让审查者看实际输出与反例，比单纯投票更有价值。成本应报告各代理调用总量、通信和最终延迟，不只挑最快的一项。

## 分工必须能追溯责任

给子任务明确输入、范围、产物与完成标准，例如“只读检查空列表行为，返回失败输入与原因”；不要只说“帮我优化”。主控负责整合，而不是把每个子结论原样拼接。收到“测试通过”时，应核对命令、环境、退出状态和输出；收到代码建议时，仍需实际实现和运行。

教师让三人分别扮演需求分析、只读审查、唯一修改者，修复上面的平均函数。[L6](/docs/ai/lab-06-tools-and-memory) 的包内 `data/coding` 已提供错误基线、契约测试和独立参考实现；先复制到沙盒运行失败测试，再修改副本。学生交付基线、差异、实际运行记录与依赖图。完整大模型编程或界面代理是选配观察，核心任务用 Python 小目录完成。

## 学生任务：预算与并行收益

A、B 各 3 单位，C 为 2，通信合并为 1。求理想串行与并行延迟、加速比。若 B 必须等 A 的结果，原并行估计哪里失效？

<details>
<summary>提示一：先画前置依赖</summary>

独立 A/B 可以同时开始；C 在两者结束后开始。通信要按题目计入并行方案。

</details>

<details>
<summary>提示二：延迟不是耗时相加的总工作</summary>

原串行 8，并行 3+2+1=6，加速比为 $8/6$。若 B 依赖 A，就不能重叠这两个 3。

</details>

<details>
<summary>完整解析与验收</summary>

理想比较加速约 1.33 倍；存在 A→B→C 依赖时主路径至少 8，若另加协调会更长。验收要求同时报告总工作、延迟与依赖，不把“两个代理”直接推导为“两倍快”。

</details>

## 独立变式与模块检查

两位代理同时读旧文件，分别修复平均值和空列表，再各写回，会发生什么？

<details>
<summary>独立完成后核对</summary>

后写者可能覆盖前者，使一个修复丢失。应使用唯一写入者整合，或在隔离分支中修改后明确合并并运行全部测试。模块验收需追踪一个系统从问题、检索、记忆、工具到终止的全链，指出每个来源与权限边界。

</details>
