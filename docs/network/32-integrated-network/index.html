综合网络设计：从需求到可验证系统

将地址、局域网、路由、传输、应用、安全与故障证据连成一个完整方案

第三十二节：综合网络设计

给四个部门分配 IP 地址并接上交换机，是否就算网络设计完成？如果学生能打开网站，却也能进入设备管理界面；或白天可用，所有人开始下载时视频会议失声，这个方案仍然不满足需求。

网络设计从需求开始，以可重复的验证结束。本页提供完整的构造案例，用于设计与故障推演；配套实验可验证其中的基础机制，但不能把小规模本机结果直接当作整个校园的容量证明。

一、需求必须可以检验

一个教学网络使用 10.20.0.0/24，建立四个广播域。数量均指需要地址的终端，不含网关；每区另留一个网关地址。

区域终端上限服务与约束
学生区90自动获取配置；可访问课件与 DNS；不得访问管理区
教职工区40可访问课件与 DNS；管理权限按身份授予
服务区20课件服务与 DNS，需稳定地址和日志
管理区10管理设备；只允许指定管理终端发起管理连接

出口的教学容量为 100 Mbit/s；视频会议需要控制排队，但不能保证远端整条路径提供相同服务。名字 course.example.net、上游 203.0.113.20 和 IPv6 文档前缀只用于构造案例。

提交的方案至少包括地址表、二层关系、路由、配置获取、应用时序、安全策略、容量估计和验证记录。每一项写清假设。

二、先规划地址，再画广播域

若平均分成四个 /26，学生区只有 62 个普通可用地址，容量已经失败。按需求从大到小做 VLSM，网关也计入使用量。

先独立选择前缀与块起点，再展开参考。

提示：容量与对齐要同时满足

普通 IPv4 子网先检查 2^(32−p)−2 是否容纳“终端 + 网关”。确定块大小后从边界开始分配，检查地址范围是否重叠；不能只挑看起来空闲的起点。

核对一种可行地址方案
区域地址块可用范围网关广播
学生10.20.0.0/25.1～.126.1.127
教职工10.20.0.128/26.129～.190.129.191
服务10.20.0.192/27.193～.222.193.223
管理10.20.0.224/28.225～.238.225.239

剩余 .240/28 可预留。四个块互不重叠；扣掉网关，终端容量分别为 125、61、29、13，满足当前需求。课件服务器取 .194、DNS 取 .195，这些固定地址不得再进入自动分配池。

VLAN 与子网在这里一一对应，是设计选择。接入端口放入所属 VLAN，交换机之间 trunk 明确允许对应标签。不同 VLAN 之间经三层网关转发；禁止访问管理区还需要访问策略，不能仅靠“有不同 VLAN”推断安全。

若增加冗余二层链路，必须配置并验证生成树等环路控制。端口上出现重复广播时，先检查拓扑和二层状态，不能用增加 IP 路由解决二层环路。

三、给转发确定完整的返回路径

R 的教学转发表包含四条直连路由；其他目标走上游默认路由。

前缀处理
10.20.0.0/25学生接口
10.20.0.128/26教职工接口
10.20.0.192/27服务接口
10.20.0.224/28管理接口
0.0.0.0/0上游下一跳，地址另由互联链路分配

学生 .10/25 请求 .194：本机判定不在自己的子网，选择网关 .1，ARP 查网关的 MAC；R 选择服务区的 /27，解析服务器链路地址并换帧。响应由 .194 发给自己的网关 .193，R 再发回学生区。没有 NAT 时，端到端目标仍是服务器，不变成网关。

访问上游也要验证返回路径。上游可配置到 10.20.0.0/24 的路由；如果实验模型采用出口 NAT，则由转换状态支持返回。NAT 不是本地四区互通所必需的功能，也不是安全策略的替代品。

在更大拓扑中，用 OSPF 传播内部路由，用 BGP 管理系统间策略；是否采用动态协议取决于规模和运维需要。不能在只有一个网关的例子里，仅靠写出协议名字就宣称验证了收敛。

四、让配置与服务互相一致

为学生区分配 DHCP 地址池 .10～.99，共 90 个地址，排除网关 .1 和预留设备。传递正确前缀、网关与 DNS .195；服务器使用固定或保留地址。DHCP 服务跨 VLAN 时要有中继并选择正确地址池。

DNS 为 course.example.net 提供 .194。TTL 例如 300 秒是一个教学选择：缓存减少重复查询，但地址变化后可能等待旧缓存到期；降低 TTL 也不能让已经建立的连接立刻改到新服务器。

应用采用 HTTPS，证书覆盖所访问名称；登录和课程权限由应用处理。网络可达、TLS 身份验证和有权下载课件分别验收。

故障推演：DNS 写成旧服务器地址会怎样

DHCP 获取可能正常，网关与新服务器的 IP 可达也可能正常，但按域名访问仍连旧地址。检查解析器与缓存中的答案、权威记录和 TTL，不能用重装无线驱动解释所有现象。

双栈扩展可给各区分别使用 2001:db8:20:10::/64、:20::/64、:30::/64、:40::/64，在每个块中配置本地 IPv6 网关。写清 RA、SLAAC/DHCPv6 和 DNS 的配置路径；IPv6 没有 IPv4 广播，不能照搬 ARP。访问策略也必须覆盖 IPv6，否则 IPv4 的拒绝规则可能被另一协议栈绕过。

五、先列通信矩阵，再实现安全规则

发起方目标允许的服务理由
学生/教职工DNS .195UDP/TCP 53解析，包括需要 TCP 的情形
学生/教职工课件 .194TCP 443；若部署 HTTP/3 再允许 UDP 443明确支持的应用版本
指定管理终端获准设备所需管理端口缩小管理入口
学生管理区拒绝不提供管理访问
其他通信各区按需求明确决定避免把默认开放当作需求

有状态策略允许已建立连接的必要返回流量，并处理所需的 ICMP 错误与路径 MTU 信息。把所有 ICMP 都封掉，可能让小请求成功而大传输失败。

防火墙限制连接，身份系统限制“谁有权限”；TLS 保护传输与服务身份。三者的边界不同。报告应包含一条允许测试和一条拒绝测试的证据，拒绝要说明依据规则还是偶然不可达。

六、容量估计需要明确口径

若 20 个学生同时下载上游网络中的课件，且没有命中本地内容缓存，每人目标应用 goodput 为 8 Mbit/s，总需求为 160 Mbit/s，已经超过 100 Mbit/s 出口，还没计算协议开销和其他通信。换成高速 Wi-Fi 并不能消除这个出口瓶颈。

访问本地 .194 的课件不经过上游出口，应检查学生接入到服务区这条路径的容量；不能把同样的本地流量也算在出口账上。

如果 RTT 为 40 ms，一个应用只有 64,000 字节在途上限，窗口约束的上限为 64,000 × 8 / 0.040 = 12.8 Mbit/s；实际吞吐还受拥塞、丢失、服务器、协议开销影响。64 KiB 与 64,000 字节也不能混用。

可以采用内容缓存、提高真正的瓶颈容量、合理调度和分时下载。QoS 只能在管理的资源上分配服务；严格优先如果没有限制，可能让其他流长期饥饿。给出类别、限额和失败时降级方式，不只写“开启 QoS”。

七、验收不是只看一个 ping

检验项要保留的证据失败时优先追问
地址配置地址/前缀/网关/DNS 与池排除表租约、地址冲突、错误 VLAN
本地交付邻居项、ARP 或 NDP 记录查询目标与广播域是否正确
跨区通信去程/回程路由与报文是否启用转发、返回路由是否齐全
应用DNS 答案、TLS 检验、HTTP 状态名称、端点、证书、资源与权限
隔离被允许和被拒绝的测试是否命中策略、IPv6 是否遗漏
性能多次测量、并发数、RTT/goodput窗口、排队、瓶颈与服务负载
恢复人为改变前后同条件检验修复是否针对已支持的原因

若只做本机实验，写明还未验证交换设备、Wi-Fi 信道或真实出口容量，不能补成“全部通过”。

八、最后一次独立迁移

改变三个条件：学生增加到 140 台；服务新增一个只能通过 IPv6 访问的端点；一个学生端终端得到错误掩码 /24。分别写出原方案哪里失效，以及要修改什么。

提示：按容量、协议栈和本地判断分别检验

先算当前学生块容量；再检查 IPv6 的配置与策略；最后让终端用错误掩码判断 .194 是否“本地”，看它会查询谁的链路地址。

核对迁移方向

140 终端加网关超过 /25 的 126 个普通可用地址，需要更大块或多个广播域；当前 /24 无法同时直接给学生一个 /24 并保留其他重叠区，应扩展总地址资源或重新规划，不能只改 DHCP 上限。

IPv6 服务要求相应地址、路由、DNS AAAA 与访问策略；只允许 IPv4 流量没有验证它。错误 /24 终端会把 .194 当作本地并尝试直接解析，正常 VLAN 隔离下无法以 ARP 跨区找到它；改回正确前缀后应交给 .1。若有代理 ARP 等例外，还需按实际设备证据解释。

提交首次设计、一次反馈后的修订以及上述变式的独立回答。用一份方案说明“每个机制为什么存在、怎样验证、改变条件后哪里先失败”，完成全课程的连接。
