# 12｜从得分到一段回答

同一个提示为什么可能得到不同回答？模型在每一步产生的是词元分布，系统还要决定怎样选择。选择规则、随机种子、最大长度和结束条件共同影响生成；它们改变输出行为，通常并不改变权重。

## 自回归是一个状态循环

初始上下文为“我喜欢”。第一步计算候选“猫、狗、书”的得分，选中一个后，把它加入输入；第二步在新增上下文下重新产生分布。模型不会一次性从固定三类概率中抽完整句子。它生成错误词后，后续条件也随之改变，因此逐步轨迹比只看最终文本更有诊断价值。

朴素贪心每次选择最高概率词元，容易复现，但可能掉进重复或局部最优。考虑第一步 A 概率 0.6、B 概率 0.4；A 后最佳结尾概率 0.4，B 后最佳结尾概率 0.9。两条路径概率分别 0.24 和 0.36，局部先选 A 不会得到这两条中最高概率的完整路径。最高概率全文也不自动等于事实正确全文。

## 温度改变分布尖锐程度

温度 $T$ 对得分做缩放：$p_i=\operatorname{softmax}(s_i/T)$。取得分 $(\ln4,\ln2,0)$，$T=1$ 时概率为 $(4/7,2/7,1/7)$，约 $(0.5714,0.2857,0.1429)$；$T=0.5$ 时指数比例为 $16:4:1$，概率约 $(0.7619,0.1905,0.0476)$；$T=2$ 时比例为 $2:\sqrt2:1$，分布更平。

温度降低使本来高得分候选更集中，没有提供新的证据，也没有修正模型偏见。某些运行时用温度 0 约定贪心，数学表达式本身不能直接除以零；记录实验时应说明运行时约定。

## 截断候选后还要归一化

以上述 $T=1$ 分布，top-k 取 $k=2$，保留前两项，重新归一化得到 $(2/3,1/3,0)$。top-p 按概率降序，保留累计概率达到阈值的最小集合。阈值 0.7 时，第一项累计 0.5714 尚不够，加第二项后为 0.8571，因此同样保留两项。阈值 0.5 时只保留第一项。

实际库对阈值边界和多种截断组合可能有不同约定，比较时要固定。采样可用累积概率：在 $(2/3,1/3)$ 中随机数 0.8 落在第二段，所以选第二项。固定种子帮助复现本实现，但不同库、版本和硬件不保证逐位一致。

## 停止不是“模型自觉完成”

模型可生成结束词元；执行器也可因最大生成数、时间、工具预算或异常停止。日志要区分正常结束和被截断。若输出 JSON 在字符串中间被截断，即使前半段看起来合理，也不是一个有效完成结果。长解释增加计算，不是正确性的证据；对算术可直接计算核验，对引用可回到来源核验。

训练通常把正确上下文并行送入模型，生成要依赖自己的选择递推。缓存可以减少重复计算，后面会讲其存储代价；它不会免除下一步选择与验证。[L2](/ai-labs/README.md) 要保存逐步候选、概率、采样规则、种子、停止原因以及未见输入。

## 学生任务：同分布不同选择

某步概率为 $(0.5,0.3,0.2)$，标签为 A、B、C。用 top-p=0.75 后，随机数 0.7 应选什么？如果用贪心又选什么？两种方法谁更能保证事实正确？

<details>
<summary>提示一：先找最小保留集合</summary>

累计 A 为 0.5，不足 0.75；加 B 为 0.8，达到阈值。保留 A、B 后需要除以 0.8。

</details>

<details>
<summary>提示二：划出归一化后的区间</summary>

A 占 0 到 0.625，B 占 0.625 到 1。随机数 0.7 落在 B 区间。

</details>

<details>
<summary>完整解析与验收</summary>

top-p 采样选 B，贪心选 A。单凭概率和选择规则无法判断事实正确，需要任务证据。验收要求把截断、归一化、抽样分成三步，并指出实际系统还须记录停止条件。

</details>

## 独立变式与模块检查

把用户提示中的一个词改掉，而保持参数和种子不变，是否保证生成相同？不保证，条件分布已改变。请不看教材画出“文本—分词—嵌入—多层计算—得分—选择—追加—停止”链；在链上标注训练会更新哪里、生成会改变哪里。能够说明因果遮挡、内部表示和采样分别做什么，才算完成语言模型计算模块。
