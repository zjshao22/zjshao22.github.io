# 第十六节：路由表怎样生成与更新

前面给定了转发表，再按最长前缀匹配选出口。现在不能继续假设那张表已经正确：校园骨干一条链路断开，谁知道故障？备用路线怎样产生？若每台路由器都凭自己的猜测改表，会不会把分组互相送回去？本节把**查已有表**推进到**建立并更新表**。

## 一、转发与路由是不同时间尺度的问题

**转发**对来到的一个分组查表并选择出口，属于数据平面的工作。**路由**收集连通性与度量信息，计算或选择候选路径，形成可安装到转发表的结果，属于控制平面的重要工作。

手工静态路由适合可控的小网络，但管理员需要维护拓扑变化。动态路由通过协议交换信息，减少逐项手工更新；它仍受配置、策略、传播延迟与故障检测约束，不能保证变化后瞬间全网一致。

路由信息库可以保留多个候选，转发表安装其中适合使用的结果。对相同前缀的候选先经过协议度量、优先关系和策略选择；分组到来时，再对已安装的不同前缀执行最长前缀匹配。**“最短路径”不取代“最长前缀匹配”。**

## 二、把网络建模成带权图

在本节模型中，节点是路由器，边是可用链路，权重表示本次约定的成本。成本可以反映配置与资源选择，不一定是地理距离、毫秒数或跳数；算法题必须先明确权重含义。

以下是**无向图教学数据**，正权重、没有额外策略。未列出的边不存在：

| 边  | 成本 | 边  | 成本 |
| --- | ---- | --- | ---- |
| A—B | 2    | B—D | 5    |
| A—C | 5    | C—D | 1    |
| B—C | 1    | D—E | 2    |
| B—E | 9    | C—E | 7    |

A 到 E 的朴素方案可以是“先选直连邻居中代价较小的 B，然后每次随便挑看起来近的邻居”。第一步并不足以保证后续路线最优，还可能绕回已访问节点。必须比较**完整路径的累计成本**，而不是只比较当前一条边。

## 三、链路状态：先获得一幅地图

链路状态方法中，每台路由器了解自己的邻接链路和成本，把这些状态向相关范围泛洪。各节点建立链路状态数据库，得到可计算的拓扑图，再以自己为起点求路径。

状态信息需要有来源与新旧判断，否则旧的“链路还活着”可能覆盖新的“链路已断”。协议通常有序列、老化与可靠传播机制；图的计算结果再转换成目的前缀的下一跳，不是把整条路径复制进每个普通 IP 分组。

常用的 **Dijkstra 算法**维护两类节点：已经确定最小距离的节点集合 N，以及尚未确定的候选。每次选择候选中当前距离最小者加入 N，然后用它更新邻居：若经它走更便宜，就降低邻居距离并修改前驱。这个贪心过程在非负权重前提下成立。

## 四、从 A 逐步计算，不跳过中间状态

记 D(X) 为 A 到 X 的当前估计。初始确定 A，到直连 B=2、C=5，其他为 ∞。括号中的字母是前驱，用于还原路径；它不是最初 A 发包的下一跳。

| 轮次 | 已确定集合 N  | B    | C    | D    | E     |
| ---- | ------------- | ---- | ---- | ---- | ----- |
| 初始 | A             | 2(A) | 5(A) | ∞    | ∞     |
| 选 B | A、B          | 2(A) | 3(B) | 7(B) | 11(B) |
| 选 C | A、B、C       | 2(A) | 3(B) | 4(C) | 10(C) |
| 选 D | A、B、C、D    | 2(A) | 3(B) | 4(C) | 6(D)  |
| 选 E | A、B、C、D、E | 2(A) | 3(B) | 4(C) | 6(D)  |

第二轮中 C 从 5 降为 2+1=3，因为 A—B—C 优于 A—C。第三轮中 D 从 7 降为 3+1=4；第四轮 E 从 10 降为 4+2=6。

沿前驱还原得到 A—B—C—D—E，成本 6。A 发往 E 的下一跳是 **B**，不是最后一条边的 D。同一棵最短路径树还给出 A 到其他节点的方向：B、C、D、E 在此模型中都先交给 B。

如果 E 后面连接某个目的前缀，就可据路由信息安装这个前缀的下一跳。现实同成本路径可能有多条，设备可采用等价多路径；本例只选择没有平局的结果。

## 五、距离向量：没有全图也能逐轮改进

距离向量方法让节点向邻居通告“我到各目的的距离”，并用邻居的估计改进自己的估计。节点 X 对目的 Y 的更新为：

`Dₓ(Y) = min over 邻居 V { c(X,V) + Dᵥ(Y) }`。

这是 Bellman-Ford 形式。X 不必获得每条远方链路的地图，但必须知道邻居给出的值以及自己到邻居的成本；它可能无法从一个数字看出邻居的路线是否反过来依赖自己。

教学链为 A—B—C—D，每条成本 1，只研究到 D 的距离。初始知道自己的 0 和直接邻居；每轮同时使用上一轮邻居通告，不使用同一轮尚未完成的新值。

| 阶段          | A 到 D  | B 到 D  | C 到 D | D 到 D |
| ------------- | ------- | ------- | ------ | ------ |
| 初始直连信息  | ∞       | ∞       | 1      | 0      |
| 第 1 轮交换后 | ∞       | 2，经 C | 1      | 0      |
| 第 2 轮交换后 | 3，经 B | 2，经 C | 1      | 0      |

第二轮 A 才得到 3，说明远方信息不是瞬间到达。它下一跳选 B，不需要知道 C—D 的每个细节；也正因为不了解全部依赖，失败信息传播可能更棘手。

## 六、坏消息慢：计数到无穷

再看两个路由器 A、B，A 原来直连目的 X，成本 1；B 通过 A 到 X，成本 2。A—B 成本 1，之后 A—X 断开。若 A 还收到 B 的旧通告“我到 X 成本 2”，可能误以为 B 有独立路径：

| 事件次序            | A 的判断  | B 的判断     |
| ------------------- | --------- | ------------ |
| 断开前              | 1，直达 X | 2，经 A      |
| A 收到 B 的旧距离 2 | 3，经 B   | 仍为 2，经 A |
| B 收到 A 的距离 3   | 3，经 B   | 4，经 A      |
| A 收到 B 的距离 4   | 5，经 B   | 4，经 A      |
| 继续互相更新        | 数字增加  | 数字增加     |

分组在 A、B 间形成环路，数字逐步增大而没有真实路径。这叫**计数到无穷**。表中的事件是特定异步到达顺序，不能把它误读成所有故障都必定采用同样时序。

**水平分割**不把经某邻居学到的路由再通告给该邻居；**毒性逆转**向该邻居明确通告不可达。它们能抑制这类两节点互相依赖，仍不能保证消除所有更复杂环路。触发更新、失效定时和协议的无穷上限也参与控制。

RIP 采用跳数度量，16 表示不可达，能表达的有限路径最长为 15 跳。较小无穷有助于结束计数，但限制了适用网络规模。[RIP 的距离向量讨论](https://www.rfc-editor.org/rfc/rfc1058.html)解释了这些机制。

RIPv2 用 UDP 520 交换信息，通告中增加子网掩码、下一跳等字段以支持无类别前缀；RIPv1 缺少明确掩码字段，不能直接当成现代 CIDR 通告的同等格式。版本改进了表达与管理能力，没有取消距离向量的计数与收敛问题。[RIPv2 规范](https://www.rfc-editor.org/rfc/rfc2453.html)给出了这些扩展。

## 七、收敛不是只算一次最短路

故障发生后，发现失败、传播变化、各节点计算、安装转发表都可能有先后。短时间内 A 使用新路线，B 仍用旧路线，就可能产生临时环路或丢包。TTL 能限制 IP 分组永久绕圈，但不能替代正确路由。

链路状态与距离向量各有状态、消息与计算成本；没有“一个总是最快且最少资源”的简单结论。动态协议还要处理抖动链路、认证与配置错误，下一节研究实际协议怎样组织这些过程。

## 八、可运行核对：让程序打印最终距离与路径

先按第四部分手算，然后把下面程序保存为 `route_demo.py`，用 Python 3 运行。它计算构造图，不连接路由器，不把打印结果当成真实校园路由。

```python
import heapq

edges = [
    ("A", "B", 2), ("A", "C", 5), ("B", "C", 1),
    ("B", "D", 5), ("C", "D", 1), ("D", "E", 2),
    ("B", "E", 9), ("C", "E", 7),
]
graph = {node: [] for node in "ABCDE"}
for u, v, cost in edges:
    graph[u].append((v, cost))
    graph[v].append((u, cost))
distance = {node: float("inf") for node in graph}
parent = {}
distance["A"] = 0
queue = [(0, "A")]
while queue:
    cost, u = heapq.heappop(queue)
    if cost != distance[u]:
        continue
    for v, weight in graph[u]:
        candidate = cost + weight
        if candidate < distance[v]:
            distance[v] = candidate
            parent[v] = u
            heapq.heappush(queue, (candidate, v))
for target in "BCDE":
    path = [target]
    while path[-1] != "A":
        path.append(parent[path[-1]])
    print(target, distance[target], list(reversed(path)))
```

交出手算轮次表、实际程序输出、以及至少一个修改权重后的预测。不要只把程序输出复制成“我理解了路由”；要说明是哪条边使某次估计降低。

<details>
<summary>第一步提示：更新只比较累计成本</summary>

到 D 已知成本 4，加 D—E 的 2，候选 E=6；不能只把边权 2 写成 A 到 E 的距离。程序中的 `candidate` 对应这一动作。

</details>

<details>
<summary>第二步提示：重新计算与重新转发分开记录</summary>

权重变化先使控制平面路径结果变化，然后影响某前缀可安装的下一跳。普通分组仍根据已经安装的表查找，不在每一跳重新跑全图算法。

</details>

## 九、独立变式：链路变贵后，第一跳会不会变

把 B—C 的成本从 1 改成 10，其他保持不变。重新计算 A 到 C、D、E 的成本与第一跳；写出完整路径，再运行修改后的程序核对。另用文字解释：两节点毒性逆转为什么不能被宣布为所有规模网络的零环路保证？

<details>
<summary>完成后核对</summary>

A 到 C 改为直接 A—C，成本 5，下一跳 C；到 D 为 A—C—D，成本 6，下一跳 C；到 E 为 A—C—D—E，成本 8，下一跳 C。到 B 仍是 2、下一跳 B。

毒性逆转向特定邻居暴露“我经你到这个目的”的依赖，能阻止本节两节点误信；多节点循环依赖仍可能经别的邻居传播，故协议还需其他失效与收敛机制。

</details>
