# 20｜视觉语言模型怎样读图回答

图文检索会给一对图文打分，为什么还不能直接回答“图中一共有几辆车”？回答需要把视觉信息接入语言生成，并按问题选择相关细节。视觉语言模型通常包含视觉编码、连接模块与语言模型，但具体架构有多种，不能由产品界面推断内部实现。

## 两种朴素方案的缺陷

只用图片文件名回答，模型可能根据 `cat.jpg` 猜中类别，却没有读取图像；只把整图压成一个平均向量，可能丢失数量、位置与小文字。测试时移除文件名、交换图片内容、改变局部细节，可检查系统是否使用真正视觉信息。

一种教学结构将 $4\times4$ 单通道图像分成四个 $2\times2$ 小块，每块投影为 4 维，得到 $4\times4$ 视觉序列；连接层把它映射到语言模型维度。若文本有三个词元，拼接后有七个位置。模型看到的是数字表示，不是直接把原始图片贴进文字的抽象比喻。

| 阶段         | 输入／输出           | 需要核查               |
| ------------ | -------------------- | ---------------------- |
| 视觉预处理   | 尺寸、裁剪、像素范围 | 是否裁掉关键角落       |
| 视觉编码     | 图像到块表示         | 局部与空间信息是否保留 |
| 连接模块     | 视觉维度到语言维度   | 是否与语言模型接口匹配 |
| 多模态上下文 | 视觉表示与问题       | 遮挡、位置及角色边界   |
| 语言生成     | 下一词元分布到回答   | 是否忠于图像与问题     |

另一种结构用交叉注意力让文本查询读取视觉键和值，不一定把全部视觉表示直接混成一条序列。两者都需要训练连接关系，单把任意数组拼起来不保证模型理解。

## 训练信号如何跨过模态连接

可以先做图文对齐，再用“图像＋问题＋示范回答”监督训练。回答词元的交叉熵梯度沿输出层回到语言模块、连接层，若视觉编码器未冻结，还继续更新视觉参数。冻结某部分只是停止其参数更新，不意味着该部分在前向中不参与计算。

用一个极小的跨模态二分类示例隔离更新：图像亮度特征 $b=1$，问题类型特征 $u=0$，回答“亮”的概率为 $p=\sigma(w_b b+w_u u)$。初始参数全零，$p=0.5$，目标为 1，交叉熵对 $w_b$ 的梯度是 $(p-1)b=-0.5$。学习率 0.1 后 $w_b=0.05$，新概率约 0.5125；$w_u$ 因输入为零未变。这是真实可训练桥梁的简化，不是完整视觉语言模型。需要多问题和反例，才能学会按问题使用不同特征。

## “看到”之后仍会错

图像模糊、小文字、密集物体计数、遮挡和空间关系都可能造成错误。语言先验也可能压过视觉：常见图像里有四条腿，模型就对被遮挡动物猜四条，而问题问的是“可见几条”。因此需要构造语言很像、图像细节不同的对照，分开评估描述、计数、定位与文字读取。

系统接受视频作为输入，不意味着能生成视频；支持图像输入，也不保证每个像素都能可靠识别。第 37 单元读模型卡时将逐项核对输入和输出模态，不能只写“全能多模态”。

教师提供同一图案配不同问题：“亮点多少”“亮点在哪边”。学生先用纸笔作答，再比较模型应取的不同特征。[L4](/ai-labs/README.md) 提供给定图文向量的匹配复算和真实训练的低维生成机制，通用大规模视觉语言系统仅在有来源的材料或具备条件的本地选配环境分析，不要求云账号。

## 学生任务：定位失败环节

系统回答“左上角文字是允许”，原图其实写“禁止”，而预处理裁剪后该角完全消失。错误应首先归咎于语言模型参数吗？设计一个能区分预处理、视觉编码与回答生成的检查序列。

</details>

<details>
<summary>提示二：逐级替换成可靠输入</summary>

先恢复角落，再用清晰局部图，再把准确文字作为文本提供。每次只改一项。

</details>

<details>
<summary>完整解析与验收</summary>

首先是输入信息缺失。检查裁剪、分辨率、局部识别与最终采用情况，必要时要求系统声明看不清。验收应保存各级输入和输出，不能只给最终正确截图。

</details>

## 独立变式

模型准确描述了图中的“红灯”，能否据此授权自动驾驶通过路口？

<details>
<summary>独立完成后核对</summary>

不能由单次描述推出控制可靠性。还需时序状态、其他交通参与者、规则、传感器与控制安全约束；视觉问答能力与具身执行是不同证据范围。这里讨论系统需求，不把课程模型用于真实道路控制。

</details>
