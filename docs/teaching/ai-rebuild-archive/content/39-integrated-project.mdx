# 39｜综合项目：定义、实现与评测

“做一个智能资料助理”无法直接验收。它应该读哪些资料，遇到矛盾怎么办，是否允许行动，怎样知道做完了？本课先把产品愿望改写成有限、可复测的任务，再组合已学部件。无需 GPU、无需模型 API 的核心入口已经在实验包内。

## 给项目写一份最小契约

推荐主线是带来源校园资料助理，使用课程虚构资料。输入为单个问题，输出包含状态、答案和来源；状态分明确回答、无证据、冲突、需澄清。可选加沙盒读取与加法，禁止真实账户动作。若采用别的主题，教师须确认材料来源、机器条件和可检查任务。

| 契约项 | 本课基线                 | 学生需要明确的变更                 |
| ------ | ------------------------ | ---------------------------------- |
| 资料   | 包内固定构造记录         | 新资料出处、版本和适用范围         |
| 检索   | BM25 与微型学习检索      | 切块、排序与相关性标注             |
| 回答   | 来源抽取与显式冲突规则   | 是否增加本地语言模型，如何单独评测 |
| 行动   | 默认不行动，可选受限工具 | 动作集合、参数、预算、回滚         |
| 记忆   | 有版本的外部记录实践     | 来源、更正、过期与跨任务复测       |

先运行 [L8](/docs/ai/lab-08-project-and-defense) 获得能够接续的基线。它真实训练检索器并执行四个对照，但核心回答器仍为规则与抽取；不要给项目换个名字就声称训练了通用助手。

## 冻结规格先于最终调优

先在 `project-spec.json` 或书面表格里定义题型、预期状态和必要证据。开发题可看、可改；最终迁移题由教师保留，完成实现后再使用。包内 `frozen_cases.json` 是公开回归规格，内容和哈希都可检查；它用于保证已知行为，不充当隐藏能力证明。

构造最小项目流程：读需求 → 建资料与来源 → 标注题集 → 跑朴素方案 → 实现检索与核验 → 固定实现 → 跑完整对照 → 保存失败与独立复测。每个阶段都产生产物，不能等界面完成后临时挑几题演示。

## 用失败决定改什么

例如闭馆问题答错，先检查是否检到临时通知，再检查实际送给回答器的材料、冲突规则和引用。若材料未检到，改提示不一定有用；若材料已在输入却被忽略，才进一步比较生成约束或回答器。修改后既重跑失败题，也重跑既有规格，防止修一题坏另一题。

同一组输入至少比较：关键词朴素基线、完整方案、移除检索、移除冲突检查。项目若增加模型生成，应保留原始返回，将格式、事实、引用和最终任务成功分别统计；不能把流畅度直接当事实质量。

## 可提交的目录与验收

提交代码、README、资料及来源说明、环境、配置、题集版本、原始日志、逐题表、基线与消融，以及个人解释。README 要让另一位同学从干净目录按命令运行，不依赖你终端里未记录的变量或未提供的文件。日志中的私人路径如需展示，应脱敏并保留结构。

教师检查三个硬条件：他人能按说明重跑；结论与输出一致；权限范围清楚。学生再解释一个失败、一个替代方案和一个未见变式。界面美观可帮助使用，但不代替这些条件。项目完成状态与学生个人理解分开记录。

## 学生任务：把模糊需求改成可验收契约

需求是“助理知道最新消息，会自动完成所有事情”。请改为四条有输入、边界和成功条件的条目，并给至少一个必须拒绝或澄清的输入。

<details>
<summary>提示一：限制资料、动作与时间范围</summary>

明确“最新”取自哪个版本，动作允许到哪一步；把“所有事情”换成有限集合。

</details>

<details>
<summary>提示二：把结束状态写出来</summary>

可规定答案须附实际检索来源、无材料时拒答、冲突时报告双方、沙盒运算须有真实结果。

</details>

<details>
<summary>完整解析与验收</summary>

合理契约可以只覆盖本周给定资料和只读查询，遇到真实账户操作拒绝，多个主题混合时澄清。验收看条目是否能被输入和输出反证，而非是否承诺得足够大。

</details>

## 独立变式

老师把资料里的电话号码从 1001 改成 1002，系统仍答旧号码。项目组接下来该提交哪些证据？

<details>
<summary>独立完成后核对</summary>

提交新旧资料版本、索引构建时间、实际检索结果、送入回答器内容和最终输出，定位缓存、索引或生成问题。不能只把报告答案手改为 1002；需要程序重新运行并留下回归结果。

</details>
