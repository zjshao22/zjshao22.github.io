第四节：封装：一个包里装着什么

分层说明了“谁负责什么”，分组交换说明了“怎样逐份传送”。两者合在一起，便产生封装：上层交给下层的数据，成为下层的负载；下层再加上自己的控制信息。

把一份请求逐层装入

以使用 TCP 的网页请求为例，浏览器先生成应用数据。TCP 将它组织成传输段，IP 把传输段装进数据报，链路层再把数据报装进当前链路的帧。发送时逐层加外壳；接收端逐层读取并交给对应的上层。

链路帧的格式会随当前链路而变。第一跳可能是 Wi-Fi，下一跳可能是以太网或其他技术；路由器接收当前帧、处理 IP 数据报，再为下一跳构造新的链路帧。图中的首部只展示所属层次，不是按真实字节比例绘制。实际协议还有更多字段、校验及可能的尾部。

发送与接收的方向

发送主机从应用层往下处理，像给一封信依次加入说明、地址和当前投递方式。接收主机从链路层往上处理，先确认这段链路交来的帧，再处理 IP 数据报、传输段，最后把应用数据交给程序。中途的普通路由器只做它承担的转发工作，不会像最终接收主机一样把 HTTP 数据交给浏览器。

所在位置主要动作
发送主机应用数据逐层向下封装，并从第一段链路发出。
中途路由器处理收到的链路帧，依据 IP 信息转发，为下一段链路构造帧。
接收主机逐层向上交付，最终让目标应用取得数据。

首部为什么不能省

每层需要不同信息。TCP 首部中的端口帮助接收主机把数据交给正确的应用端点；IP 首部中的目标地址帮助路由器转发；链路首部服务于当前一跳。如果只剩网页正文，路由器不知道往哪里转，接收主机也难以判断该交给哪个程序。

同一份数据，三种交付范围
链路送到相邻设备
IP送往目标主机的网络位置
传输交给目标主机上的应用端点

一个容易混淆的词：包

日常说的“网络包”可能泛指多种协议数据单位。讨论具体结构时，应说清链路帧、IP 数据报、TCP 段。它们有嵌套关系，却不是三个分别发送的独立物件。BitTorrent 的“文件片段”则是应用层拆分文件的单位，和这里的协议单位处于不同层。

用一个对照检查是否真正分清：如果文件共享应用把文件切成 100 个片段，不能推出网络里恰好有 100 个 IP 数据报。每个应用片段可能需要很多数据报；传输层和网络层如何分段还会受数据大小及链路条件等限制。
