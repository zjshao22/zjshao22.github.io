以太网与交换机如何送达一帧

读以太网帧，用源地址学习、目的查表和老化解释局域网转发

第十一节：以太网与交换机如何送达一帧

上一单元知道了下一跳的 MAC 地址，却还没有解释交换机怎样把帧送到那个接口。一个朴素方法是每次向所有端口复制：确实容易找到目标，但每台电脑都要承受别人传送的负担。另一种方法是提前手工登记每个 MAC：电脑移动、网卡更换后登记又会过期。交换机需要从日常流量中学习，并在信息不足时仍能送达。

一、先读清楚以太网帧

普通、没有 VLAN 标签的 Ethernet II 帧包含目的 MAC、源 MAC、EtherType、载荷与 FCS。以下大小不含物理层前导码和帧间间隔，也不讨论巨型帧：

字段字节数用途
目的 MAC6当前链路的接收目标
源 MAC6当前发送接口
EtherType2指示载荷协议，如 IPv4、ARP、IPv6
载荷与必要填充46～1500携带上层数据，短帧需要填充
FCS4CRC 错误检测

因此常见无标签帧从目的地址到 FCS，最小 64 B、最大 1518 B。1500 B MTU 指载荷可以容纳的网络层分组大小，不含这个 14 B 首部和 4 B FCS。Ethernet II 的类型值用于分用；IEEE 802.3 的长度/LLC 形式还有其他解释，不能把每一种帧格式都叫 Ethernet II。

例如一个 28 B 的 ARP 报文需加 18 B 以太网填充，随后附加首部和 FCS，得到 64 B。填充不会变成 ARP 报文的一部分。

实际抓包常不显示前导码、FCS或填充，因为网卡与驱动在交给抓包程序以前已经处理。看到 42 B 的 ARP 记录，不意味着物理链路真的发送了不满足最小长度的帧。

二、MAC 地址不是网段地址

MAC 地址标识链路层接口。一个主机可能有多个接口，虚拟接口也可以有 MAC；地址还可以被软件配置或随机化，因此不要把它看成永不可变的机器身份证。

以太网有单播、广播、组播。广播地址为 ff:ff:ff:ff:ff:ff；组播用于选定接收者集合。网卡通常接收自己、广播以及它加入的组播等帧，而非把看到的每一帧都交给应用。

IPv4 前缀表达网络位置，MAC 不表达“先去哪个城市、哪栋楼”。交换机通常按当前 VLAN 的 MAC 表查找出口；路由器则按 IP 转发表选择下一跳，并为下一条链路重新构造帧。这个差别解释了为何跨路由器时链路地址改变，而普通转发中的 IP 目的仍指向最终主机。

三、交换机怎样从源地址学习

假设帧从端口 3 进入，源 MAC 为 A。交换机就知道“到 A 的帧可以朝端口 3 发”，把 (VLAN, A) → 端口 3 记入转发表并刷新老化时间。

它没有因为目的为 B 就知道 B 在端口 3；入口的位置只证明源从哪里来。目的地址只是待查找的对象。学习可以在没有 ARP 的情况下发生，ARP 表也不是交换机的 MAC 转发表。

收到合法帧
确定入口与 VLAN
读取源 MAC
学习或刷新源的位置
将源 MAC 关联到入口端口
查目的 MAC
决定出口
已知目的定向转发；未知目的在同一 VLAN 泛洪
排队发送
按出口链路传送
必要时处理 VLAN 标签；入口端口不再收到同一份普通泛洪副本

有三种常见情况：

  • 目的已知且在另一个转发端口：向该端口发送。
  • 目的已知且就在入口端口：过滤，通常无需把帧送回同一段。
  • 目的未知单播或广播：在该 VLAN 的其他合适转发端口复制，称为泛洪。

组播可以使用专门的组播转发表或侦听机制限制复制；本节的练习把没有相关信息的组播作为需泛洪的情况。

四、逐帧建立一张表

以下是教学构造数据。一台交换机有端口 1=A、2=B、3=C、4=上联，均属同一 VLAN，全部转发且没有环路。初始 MAC 表为空，过程没有老化或移动；A、B、C 为三个不同的单播地址。

次序入端口源 → 目的
11A → B
22B → A
33C → B
41A → C
52B → 广播

对每帧先写“学到了什么”，再写“向哪些端口发送”。不要先查目的再猜源所在的位置。

第一步提示：第一帧只让 A 变成已知

A 从端口 1 发来，所以记录 A→1。B 尚未出现为源，仍未知；泛洪到端口 2、3、4。

完成后核对整段状态
次序学习后 MAC 表出端口原因
1A→12、3、4B 未知
2A→1，B→21A 已知
3A→1，B→2，C→32B 已知
4A→1，B→2，C→33C 已知
5A→1，B→2，C→31、3、4广播不因已学到地址而变成单播

第三帧不需要知道任何 IP 地址，就能向 B 所在端口发送。第一帧的未知单播泛洪也不等于其目的 MAC 被改成广播地址。

五、老化与移动为什么必需

如果 A 拔掉网线，旧记录不能永久保留。动态记录在一段时间没有刷新后老化删除；具体时间由实现和配置决定。下一次有人发向 A，交换机可能先泛洪，直到重新从 A 的源地址学习。

若 A 移到端口 4，下一帧从 4 进入且源为 A，动态表通常更新为 A→4。这个机制适应移动，也会受到地址冒用影响；端口安全、认证等机制在安全单元继续讨论。

MAC 表老化、ARP 缓存过期、IP 路由失效是三个不同事件。前者可能增加泛洪，ARP 过期使主机重新解析邻居，路由失效使路由器重新选择或失去路径。把它们统一叫“地址没了”，就无法定位故障。

六、集线器、交换机与路由器

集线器在物理层重复信号，连接者共享一个冲突域。交换机按链路地址决定出口，点到点端口可分别传送；同一 VLAN 的广播仍可能经过多个交换机到达所有成员。路由器连接网络层网段，不按通常的 IP 转发规则扩散链路广播。

现代常见以太网采用交换式点到点全双工。一条链路两端可同时向相反方向发送，普通全双工模式不使用 CSMA/CD 来处理冲突。交换机仍可能因为多个输入竞争同一个出口而排队与丢包；没有冲突不意味着没有拥塞。

历史共享、半双工以太网使用 CSMA/CD：先监听，空闲时发送；边发送边检测冲突；检测后停止并退避重试。距离导致监听信息有延迟，所以“先听空闲”不能完全避免碰撞。

发生多次碰撞后，退避从越来越大的范围随机选等待时隙。最小帧长度和网络跨度的历史约束使最远端碰撞能在发送结束前被发现。这解释了传统机制的设计，而不是宣称当代全双工校园交换链路都在碰撞。

七、实际观察：一帧与一次 IP 通信

在自己电脑上用已有 Wireshark 抓取自己有权观察的活动接口流量，过滤 arp or icmp，再对本地网关发少量 ping。若当前接口是 Wi-Fi，抓到的可能是驱动提供的以太网式表示，不能据此宣称空中帧没有 802.11 地址字段。

选择一个 ARP 请求和一个 ICMP 报文，记录源/目的 MAC、EtherType、源/目的 IP，以及显示的长度。若没有 ARP，可能是缓存已存在；若只支持 IPv6，应转到第十四节的邻居发现观察。不要清除全校设备的缓存或向不属于自己的端口发送测试流量。

交出两份报文字段对应表，并回答：发往远方服务器时，当前以太网目的 MAC 为什么通常是本地下一跳？一台普通电脑的抓包只能看到被送到其接口的流量，不能直接重建交换机所有端口的泛洪轨迹。

观察提示：看不到 FCS 不代表没有错误检测

记录抓包接口、操作系统和抓包长度。驱动可能去掉 FCS，校验卸载也会影响界面提示；不要仅凭抓包显示给线路下结论。

第二步提示：抓包接口不是交换机的完整视角

如果一个帧从交换机其他端口定向传走，自己的普通终端未必收到；混杂模式也不会让交换机自动把全部其他端口流量送来。要证明具体交换行为，需要合适的实验拓扑、端口镜像或交换机状态。

同一 VLAN 的多交换机学习

若 A 接 S1、B 接 S2，两台之间只有一根正常上联，S2 收到来自 A 的帧，会把 A 学在自己的上联端口。它只需知道方向，不必知道 A 最终插在 S1 的哪个终端口。S1 则在收到 B 作为源的流量后，把 B 学在自身上联。

所以每台设备的 MAC 表是本地“目的到方向”的记录，不能把 S1 的端口 3 直接复制成 S2 的端口 3。上联上可以学到许多终端地址，并不表示所有这些地址都属于交换机本身。

八、独立变式：改变状态再转发

沿用第四部分最终表。C 的记录先老化删除；A 仍在端口 1，B 仍在端口 2。依次收到：端口 1 的 A→C；端口 4 的 C→A；端口 2 的 B→C。写出每步表和出端口。再说明：是否应该把 C 的 IP 地址改成端口编号？

完成后核对

第一步泛洪到 2、3、4，因为 C 未知。第二步学习 C→4，向已知 A 的端口 1 转发。第三步向端口 4 转发，C 的旧端口 3 不再使用。MAC 学习记录的是链路方向，不修改 IP 地址，更不会把端口编号当作 IP。

以太网帧中 IP 数据的封装与填充，可核对RFC 894；交换式与历史共享以太网的区别，可核对以太网机制说明。
