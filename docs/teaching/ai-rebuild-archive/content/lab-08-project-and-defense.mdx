# L8｜综合项目与独立复测

对应 35—40 单元。先复现课程小系统，再完成一个有明确变更的个人或小组项目。无需购买 API；核心系统为学习检索器加来源抽取和显式规则。

```sh
python3 -B ai_lab.py l8 --output ./runs/l8 --seed 42
```

## 先核对固定规格

`data/frozen_cases.json` 保存七道公开回归题：明确答案、无证据、冲突和跨主题澄清。源码记录发布哈希，程序运行前后核查文件未变。它是开发者可见的规格，不能叫隐藏能力评测。

教师运行前让学生预测四种方案在哪类题会失败：关键词朴素抽取、完整学习检索与规则、移除检索、移除冲突处理。学生再对照 `summary` 和逐题 `results`；即使完整方案全对，也只证明该次公开规格。

## 做一个能归因的项目变更

按[第 39 单元](/docs/ai/39-integrated-project)确定资料范围、输入输出和权限。可新增版本材料、改切块、加入记忆更正、增加受限工具，或对本地生成分支做独立评测。先保存原基线，每次只改变可解释的条件，新增数据和规则注明来源。

最终提交代码、环境、资料说明、冻结题集、配置、原始日志、逐题表、基线消融与失败解释。教师检查另一位同学能否按 README 从干净目录运行，不能依赖作者未说明的本地文件。

## 再做个人独立复测

教师保留最终陌生题，改变数字、资料版本或权限约束。每位学生先预测，再独立追踪一次实际运行；必要提示按三级给出，并记录是独立还是提示后完成。多人完成的项目不自动证明每人都能解释。

项目题型示例不作为隐藏题：新增临时闭馆记录、给出同名异义材料、工具要求越权、记忆更正发生在另一字段。最终现场值由教师另定，不把本文公开示例称为未见数据。

## 学生任务与验收

运行默认规格并解释一个消融失败；再提交项目变更及原规格回归；最后完成个人口述与现场变式。教师分别记录工程运行、机制理解和迁移表现，不将网页制作完成写成已授课或已掌握。

<details>
<summary>提示一：平均分不能替代逐题表</summary>

找 `failure_ids`，回到相应问题、状态和引用，再定位组件。不要先手改预期答案求通过。

</details>

<details>
<summary>提示二：消融体现的是当前任务条件</summary>

移除冲突门控在冲突题失败，支持它在此规格的作用；不能推广为所有系统都须采用同一规则实现。

</details>

<details>
<summary>完整解析与最低验收</summary>

合格证据包括原规格哈希、四种方案逐题结果、项目变更和个人复测。若新规格确需变更，另存版本并说明理由；不要覆盖原发布规格后仍声称它未改。

</details>

## 独立变式

将任务换成另一套有来源的虚构资料，不改题目标签猜规则，重新标注相关证据与预期行为。报告哪些组件可复用、哪些规则需改，以及失败为何发生。最终结论限定到运行与课堂实际观察。
