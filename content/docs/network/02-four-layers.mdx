# 第二节：校园网里的四层分工

在宿舍打开课程平台，数据可能先经过无线接入设备，再经过校园网络、运营商网络，最后到达提供服务的设备。若浏览器必须知道每段网线和每台设备的细节，换一个宿舍或换成手机流量，应用就得重写。互联网采用**分层**：把大任务分给几个职责明确的层，上层使用下层提供的服务。

## 一、先认清路径上的角色

- **主机**：发起或接收通信的设备，例如你的笔记本和提供课程页面的服务器。
- **链路**：相邻设备之间传数据的一段连接，例如宿舍 Wi-Fi、校园里的有线连接。
- **接入设备**：把你的设备接入网络。无线接入点负责无线接入；生活中称为“路由器”的盒子也可能同时承担接入和路由功能。
- **路由器**：连接不同网络，根据目的地信息决定把数据交给哪一个下一跳。

“一跳”指数据从当前设备跨过一段链路到达相邻设备。图中省略了许多设备；校园平台也可能部署在校内，因而不必经过运营商公网。不要把图读成所有学校都有完全相同的线路。

## 二、四层各自回答什么问题

| 层     | 要解决的问题                                               | 在打开课件时的例子                                        |
| ------ | ---------------------------------------------------------- | --------------------------------------------------------- |
| 应用层 | 这些数据表达什么要求？                                     | 浏览器请求“网络基础”课件；HTTP 规定网页请求与响应的含义。 |
| 传输层 | 把数据交给目标主机上的哪个通信端点？需要怎样的端到端服务？ | 端口帮助区分服务；TCP 可提供可靠有序的字节流。            |
| 网络层 | 数据怎样跨越多个网络，朝目标主机前进？                     | IP 地址标识网络中的目标位置；路由器转发 IP 数据报。       |
| 链路层 | 这一跳怎样把数据交给相邻设备？                             | 第一跳可能使用 Wi-Fi，后续可能使用以太网等技术。          |

可以把它看成四个不同的问题：**要什么内容？交给哪个程序？送往哪个网络位置？当前这一跳怎么送？** 这四个问题会在一次访问中同时出现，但不能用同一个词回答。

### 域名、IP 地址与端口不是同一件事

人在浏览器输入网站名称或网址；需要时，**DNS** 会帮助把主机名解析为可用的 IP 地址。IP 地址给跨网络转发提供目标信息。数据到达目标主机后，端口等传输层信息帮助它找到相应的服务端点。课件路径则告诉应用要返回哪一项内容。DNS 是名称查询服务，**不是网页数据必经的一台转发路由器**；解析结果也可能来自缓存。

例如“学校课程平台”是你理解服务的名称，“这台服务器的可用 IP 地址”用于网络转发，“HTTPS 服务端点”用于把通信交给合适程序，“网络基础课件”才是具体资源。一个站点可以有多个地址，真实服务也可能经过代理或缓存，所以这里只讨论职责，不给某个真实平台画固定路线。

## 三、为什么分层有用

你从宿舍 Wi-Fi 切换到手机流量，第一段链路变了；课程平台仍可以通过共同的 IP 网络服务被访问。学校更换无线设备，不必因此改写每一门课的网页。不同应用也可以复用同一套网络层能力。这种让很多链路技术和很多上层应用通过 IP 协作的结构，常被形容为互联网的**细腰**。

分层还帮助定位故障。若电脑根本连不上宿舍 Wi-Fi，先检查接入与链路；若网页已经返回“课件不存在”，先核对应用层的资源信息。它不是说各层完全互不影响：拥堵的链路会让网页加载慢，传输服务也会影响应用体验。分层的重点是**明确每层的直接责任**。

## 四、把任务放回对应的层

看下面四个动作，先自己判断直接负责的是哪一层，再对照解释：

| 动作                                 | 直接负责的层 | 原因                         |
| ------------------------------------ | ------------ | ---------------------------- |
| 浏览器解释“获取课件”这个请求         | 应用层       | 它理解资源的含义。           |
| 目标设备把收到的数据交给对应服务端点 | 传输层       | 它使用端口等信息区分端点。   |
| 路由器根据目标 IP 信息选择下一跳     | 网络层       | 它处理跨网络转发。           |
| 设备在当前无线连接上传一帧           | 链路层       | 它只处理相邻设备之间的传送。 |

如果答错了，不要只改层名；试着说出这个动作处理的是“资源、程序、主机位置”还是“当前一跳”。

## 五、服务、协议与对等实体

分层时要区分两个方向：**同一设备里，上层使用下层提供的服务；不同设备上，同层功能依据协议协作。**浏览器调用系统网络接口，是向下使用服务；两个端点用 HTTP 语义交换请求与响应，是应用层对等实体的协作。路由器转发 IP 数据报时，不需要成为浏览器的 HTTP 对等方。

每层处理的数据也有不同称呼：应用层可说“应用消息”，TCP 的单位常称“段”，IP 的单位是“数据报”，以太网链路传送“帧”。一个 2 MB 的课件不可能因为被称作“一份文件”，就在网络中只成为一个数据报；数据会分成许多段、数据报和帧。

### 端到端与逐跳

浏览器与课程平台服务程序位于通信两端。TCP 的连接状态主要由两端维护；IP 数据报被沿途路由器逐跳转发；以太网或 Wi-Fi 帧只对当前链路有效。经过路由器后，旧帧被处理，下一段链路使用新的帧。即使帧的目标 MAC 地址变化，普通转发中的 IP 最终目标仍是同一台服务器。NAT、隧道、代理等中间功能会使实际可见的地址和端点更复杂，本课先以普通转发为基线。

## 六、用五个标识分析同一次访问

假设浏览器访问教学地址 https://course.example.com:443/courses/network，且解析得到示例 IPv4 地址 203.0.113.20。以下值仅供推理：

| 标识           | 示例值              | 回答的问题                   |
| -------------- | ------------------- | ---------------------------- |
| 主机名         | course.example.com  | 访问哪个命名的服务？         |
| 目标 IP        | 203.0.113.20        | 数据报向哪个网络层目标转发？ |
| 目标端口       | TCP 443             | 到达主机后交给哪个服务端点？ |
| 路径           | /courses/network    | 这个服务中的哪个资源？       |
| 第一跳链路地址 | 本地网关的 MAC 地址 | 当前帧先交给哪个相邻接口？   |

**TCP 连接不能只靠目标端口唯一标识。**在简化的 IPv4/TCP 情境中，源 IP、源端口、目标 IP、目标端口共同区分通信，传输协议类型也须已知。同一服务器的 443 端口可以同时服务许多客户端，因为它们的源地址或源端口不同。客户端的临时端口由系统选择，不能把 443 误认为双方都使用的端口。

### 例题与解析

宿舍电脑显示 Wi-Fi 已连接，但浏览器提示“无法解析主机名”。这表明无线接入至少已有某种连接状态，却**不能证明 DNS 查询成功**。先检查主机名拼写、DNS 配置及解析结果。若主机名能解析、连接也建立，但返回 HTTP 403，则继续核对应用权限与登录状态。

**题 1：**改用手机热点后，第一跳帧的地址和目标 IP 必定保持原样吗？**答：不是。**第一跳链路信息会随接入改变；本机 IP、解析结果和网络出口也可能改变。分层允许应用逻辑继续工作，不保证每个地址数值固定。

**题 2：**两名学生同时访问同一服务器的 TCP 443 端口，服务器怎样区分连接？**答：**各连接的源地址、源端口和目标地址、目标端口等信息组合不同；仅“目标端口 443”不足以唯一定位连接。
