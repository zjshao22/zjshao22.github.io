第三节：IP 如何把数据送向终点

设想电脑 A 要向服务器 B 发送数据，中间没有一根直连的线。数据先到本地路由器，再经过其他网络。每台路由器只需要决定接下来交给谁，不必提前掌握从 A 到 B 的完整路径。

数据报：带着目的地出发

IP 接收上层数据，把它放入数据报。数据报由首部和负载组成：首部含有源 IP 地址、目标 IP 地址等控制信息；负载承载上层数据。路由器查看目标 IP 地址，结合自己的转发表选择下一跳。

可以把转发表想成路口的指示牌：它告诉当前路由器“往这个目标方向，应从哪个出口走”。它通常不保存“每个数据报走过的全部路口”。真实转发表匹配的是地址前缀，具体规则会在学习 IPv4 与路由时展开。

IP 给出什么承诺

原讲义把 IP 服务概括为：数据报、尽力而为、不可靠、无连接。这些词各有含义。

  • 数据报：每份数据带着足以让网络逐跳处理的地址信息。
  • 尽力而为：网络会尝试交付，但不承诺一定到达，也不保证时间、顺序和不重复。
  • 无连接：IP 转发之前不需要为这一组数据报建立一条端到端的专用电路；路由器通常不为每条应用通信保存传输状态。

“不可靠”不等于“平时完全不能用”。它说的是协议没有交付保证。如果某份数据报丢了，需要上层协议或应用决定是否检测和补救。TCP 的确认与重传是一个常见答案，但那属于传输层。

为什么要分成包

如果一个人传文件时独占整条链路，其他人的短消息只能一直等。分组交换把数据切成可独立处理的包：不同用户的包可以交替通过同一条链路。路由器收到包后查看首部，若出口空闲就发送；若出口忙，包可能排队。队列满了就可能丢包。

这个设计让很多通信共享网络资源，也带来排队延迟和丢失的可能。它不保证每个包都走相同路线，包的到达顺序也可能变化。

想象出口每次只能送一份包，队列最多等待两份。若 A1 正在发送，B1 和 A2 已经排队，此时 B2 又到达，它就可能因队列没有位置而被丢弃。换一个到达顺序，丢掉的也可能是别的包。“发送端先发出”不能推出“接收端先收到”，因为沿途各处的等待和路径可能不同。
