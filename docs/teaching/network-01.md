# 计算机网络第一课教师卡（约 120 分钟）

对应学生页：`content/docs/network/01-how-web-works.mdx`。本卡不参与静态站点导出。

## 本课取证

- **学生自己决定**：新网址访问中各角色的任务与先后；故障发生在哪一阶段；根据现象给出证据。
- **已演示内容**：`media.example/intro` 的简化首次访问路径；DNS、IP、TCP/UDP、HTTP 的职责；404 与解析失败的区别。
- **独立任务**：`notes.example/chapter1` 的 A/B/C 三种情境。要求学生自己画图并写证据，不能只复述术语。

## 独立任务参考判断

- A：如果名称没有解析为可用地址，示例中尚未取得该站点的 HTTP 404 响应。需确认错误确实是该主机名的解析失败，而不是把浏览器任意错误页都称作 DNS 错误。
- B：收到该站点的 HTTP 404，说明请求已得到应用层响应；名称定位与到达能响应 HTTP 的端点等步骤已经有了结果。接着检查目标路径、资源是否存在或是否被改名。不要说“404 证明链路每一跳都完全正常”。
- C：比较两个 URL 的主机名、路径、状态码与请求记录。若首页和目标路径主机名相同且后者为 404，优先核路径；若目标请求根本未发出或被浏览器拦下，要用面板和报错内容继续区分。

## 易错口径

- DNS 解析器是查询对象，不是网页数据转发链上的固定一跳。
- 路由器选择下一跳；它不读取网页正文来决定要去哪里。
- TCP 提供可靠按序字节流；“可靠”不等于链路永不失败。
- UDP 本身不保证交付；QUIC 在 UDP 之上实现自己的可靠传输。
- HTTP 404 是应用层响应，不等于“整个网络断了”。
- HTTPS 保护内容与完整性，但不保证隐藏所有通信元数据。

课堂上若设备无法打开开发者工具，用内嵌请求路径演示完成同样的阶段记录即可。演示模型明确限定为首次访问、无可用缓存、基于 TCP 的 HTTPS；不把它说成所有浏览器访问的唯一流程。
