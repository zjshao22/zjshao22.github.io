# 计算机网络讲授提示

完整设计、主教材、章节映射与教师侧 AI 工作流见 [计算机网络课程设计](./network-course-design.md)。本文件只保留讲授边界与协议核验依据。

学生没有配套讲义。学生页面必须独立提供术语定义、例子、图示、练习与判断依据；课堂讲授和课后阅读都不应依赖打开参考仓库或 PDF。图示使用页面组件绘制，不用空格和字符拼出依赖字体对齐的图。

## 原有取材与本轮依据

内容借鉴了 [Introduction to Computer Networking 第一单元讲义镜像](https://github.com/khanhnamle1994/computer-networking) 的概念顺序：应用需求、四层模型、IP 服务、分组交换、封装、网络字节序、IPv4、最长前缀匹配和 ARP。学生页面已改用国内学生熟悉的校园网、班级群、铁路查询、国内视频平台等情境。所有具体路径和拓扑均标为教学模型，不声称是真实平台的内部实现。参考讲义有些硬件或年代相关的描述已经过时，本课程只保留仍适用的协议原理。

上述镜像保留为历史取材记录。本轮以课程设计文档确立的官方开放教材统一后续组织与核验。教材、参考库与教师课程规划不列在学生页面；页面自身给足学习所需的信息。

地址例子依据 [RFC 1918](https://www.rfc-editor.org/rfc/rfc1918.html) 的私有地址块和 [RFC 5737](https://www.rfc-editor.org/rfc/rfc5737.html) 的文档示例地址块；ARP 的请求与应答依据 [RFC 826](https://www.rfc-editor.org/rfc/rfc826.html)。这些链接供教师核对，学生页不依赖外部讲义。

HTTP 语义参考 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)，TCP 参考 [RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html)，IPv4 参考 [RFC 791](https://www.rfc-editor.org/rfc/rfc791.html)，CIDR 参考 [RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html)。浏览器网络面板操作核验依据为 [Chrome DevTools 官方文档](https://developer.chrome.com/docs/devtools/network)。ARP 页采用以太网逻辑链路模型；无线接收地址与逻辑目的地址的区别可用 [Cisco 的 802.11 帧说明](https://community.cisco.com/t5/networking-knowledge-base/802-11-frames-a-starter-guide-to-learn-wireless-sniffer-traces/tac-p/3805605) 核对。

## 讲授重点

- 先让学生说清“哪个程序向哪个程序要什么”，再引入层次。
- 区分资源路径、端口、IP 地址和当前链路；不要把它们合称“网址”。
- IP 的尽力而为是“没有交付保证”，不等于网络平时不能使用。
- 路由器逐跳处理网络层信息，当前链路帧可能在下一跳改变。
- 404 是应用层响应，不能直接解释为宿舍 Wi-Fi 断开。
- 以太网帧的两个地址不能直接照搬为 Wi-Fi 帧的所有地址字段；ARP 的 IP 到链路地址映射与无线传输给 AP 的过程需要区分。

## 检查理解

让学生先独立回答页面中的问题，再展开解析检查理由。观察或推演任务保留过程与结果，迁移题改变关键条件，用来检查学生是否只记住了原答案。第四节的综合段落可以检验学生是否能把应用、传输、网络、链路及封装连成同一次通信。第八节再要求学生说明：目标 IP、下一跳 IP、第一跳链路地址分别指谁，以及缓存命中怎样改变这次操作。
