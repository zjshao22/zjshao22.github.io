# 32｜本地模型与 CPU 推断

下载一个模型文件，为什么有时仍不能回答？文件可能只有权重，没有分词器、结构配置或兼容运行时；也可能能加载，却因内存不足而无法完成长回答。先把“文件存在”“能推断”“能完成任务”分成三个可检查状态。

## 一个可运行模型至少需要什么

第 11 单元的计算图规定结构，训练检查点提供参数；分词器把输入变成与权重词表一致的编号，运行时实际执行运算。对话模板再把角色与消息组织成模型训练时认识的格式。随意换词表，即使维度相同，也会使编号的含义错位。

| 项目           | 课堂核查                         | 失败时的观察             |
| -------------- | -------------------------------- | ------------------------ |
| 结构配置       | 层数、隐藏宽度、词表与权重形状   | 加载失败或计算形状错误   |
| 分词器         | 同一文本的编号与还原结果         | 输入被错误解释           |
| 权重           | 文件版本、哈希、精度、许可入口   | 文件损坏或版本不一致     |
| 运行时         | 版本、CPU 后端、支持的文件格式   | 文件可读但算子不支持     |
| 对话与采样配置 | 角色模板、上下文、输出上限、种子 | 格式异常、截断或无法结束 |

开放权重只说明某些权重可以按相应条款取得，不自动意味着训练数据、训练代码和完整复现条件均已公开。学生记录各部件来源与许可说明的位置，不从“可下载”推断任意用途均被允许。核心实验的代码和构造数据随包提供，无须下载通用模型。

## 先估存储，再测进程

假设有 $P=10^9$ 个权重，每个以 16 bit 保存，仅权重约占 $2\times10^9$ 字节，即约 1.86 GiB；8 bit 约 0.93 GiB。这里 GiB 的分母为 $2^{30}$。实际文件还可能含尺度、分组信息和元数据；运行中还需缓存、激活和程序内存，不能把这两个数字当作最低可用内存承诺。

朴素方案将所有浮点权重直接取整，会把很小的值抹掉。对称量化可以先选尺度 $s=\max|w|/127$，再令 $q=\operatorname{clip}(\operatorname{round}(w/s),-127,127)$，恢复近似为 $\hat w=sq$。对 $w=(-1,0.3,1)$，尺度为 $1/127$，得到 $q=(-127,38,127)$，恢复中间值约 0.2992。全零向量另令量化值全零并采用非零尺度，避免除零。量化引入误差；异常大的单个权重还可能让其他值的有效精度降低。

线性层若输入也量化，先累加整数 $\sum_jq_{w,j}q_{x,j}$，再乘两端尺度。整数累计范围必须足够大。实际高效实现还依赖 CPU 指令、算子和布局；Python 循环中的整数版本可能更慢，文件更小不能直接推出速度更快。

## 本课真实实验与本地预训练模型分支

运行 [L7](/docs/ai/lab-07-resources-and-adaptation) 比较 32 个 float64 权重的 256 字节，与 32 个 int8 加一个 float64 尺度的 40 字节。检查 `quantization.weight_mse`、整数累计和两种调用耗时。这里没有把 Python 对象占用计入文件字节，学生须明确报告测量口径。

需要观察通用预训练模型时，使用 [环境与本地推断页](/docs/ai/lab-00-environment) 中的独立分支。它只访问本机回环，显式禁用 GPU，不自动下载权重。需记录已安装实例、权重摘要、运行时、CPU/内存、请求、返回和耗时。调用失败也是有效记录，不能用抽取答案替代后报告“模型回答成功”。

教师先用微型网络保证全班有可运行路径，再依据本机诊断安排通用模型观察。制作机跑过一次，也不能证明全部学生电脑已准备好。学生提交模型组成表、存储复算和实际运行记录；任何生成内容仍需按任务验证。
