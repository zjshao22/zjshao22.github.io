# 数据库原理及应用：完整课程设计（64 学时）

本课程围绕一个明确结果组织：学生能够独立完成现有四个实验，并能在题库之外的同类场景中完成数据库设计、SQL 编写和概念判断。

教学主线采用“学生选课与成绩管理”：认识数据 → 建立四张表 → 操作和查询数据 → 解释与改进设计 → 管理数据库 → 接入成绩管理程序。图书、销售、仓库、运动会等场景用于检验迁移能力。

## 一、设计依据与边界

学生基础按已确认的条件设定：具备基本计算机操作能力，没有 SQL 基础。课程总量为 64 学时；排课换算暂按每学时 45 分钟，学校采用其他时长时按模块比例调整。

设计依据为 `docs` 下四份实验要求、2026 春机考复习题库，以及 `p1data.zip.zip` 中的 `p1data.sql`。

| 现有材料                       | 直接提出的学习要求                                                              | 对课程的影响                                           |
| ------------------------------ | ------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 实验一：MySQL 库表操作查询综合 | Workbench 图形化建库建表、导入数据、3 道增删改、15 道查询、提交报告和数据库文件 | SQL 与上机操作是核心；实验必须分阶段推进               |
| 实验二：数据库设计             | 任选一个系统，完成需求、概念、逻辑与物理设计，解释 ER 转关系模式规则            | 必须训练完整设计过程与表达，不能只教画 ER 图           |
| 实验三：MySQL 数据库管理       | 数据、表、整库的备份还原；创建用户、改密码、建立连接和授权                      | 必须区分 SQL 编辑器、系统终端、数据库账户及权限范围    |
| 实验四：数据库应用开发         | 四张业务表；教师登录注销、查看任课选课情况、增删选课、录入和修改成绩            | 必须补足数据库与程序之间的连接，检查教师身份与数据范围 |
| 2026 春机考题库                | 90 分钟；单选 20 分、判断 15 分、设计 15 分、综合应用 50 分                     | 要同时训练实际执行与脱离客户端独立写答案               |

题库包含 75 道单选、70 道判断、15 道设计题和 5 套综合应用题。设计题分为 ER 设计、ER 转表、规范化各 5 道；每套综合应用有 12 个子题，结构相同：建库 1 题、建表 1 题、增删改 3 题、查询或数据库对象 6 题、关系代数 1 题。

机考说明以主观题为主，没有承诺提供可执行 SQL 的数据库环境。因此，课堂上机和机考书写分别训练：前者证明能够操作与验证，后者证明能够独立组织答案。

实验四的编程基础另作条件处理。学生有已学语言时沿用该语言；学生没有编程基础时，由教师后续提供可运行的最小项目骨架，学生完成数据库连接、查询与修改功能。64 学时方案中的应用开发部分以此为前提。

## 四、各模块的教学取舍

### M0—M1：先建立学生能理解的四表模型

从学生、教师、课程、选课记录解释“实体表”和“联系表”，重点让学生理解成绩为什么属于选课记录，为什么选课表需要联合主键。

Workbench 的图形化建表是实验一明确要求，必须练习；同时要求学生能够读懂对应的表定义，并逐步独立书写建表语句，以衔接机考。

数据库系统概念嵌入实际操作：谁是客户端、谁管理数据、谁负责管理数据库。三层模式及数据独立性在此建立直观对应，在后续设计和管理模块中复习。

### M2：把读题训练放在语法记忆之前

每道题先确定“结果中的一行代表谁”，再确定输出哪些列、去哪里找、满足什么条件、如何排序。要求学生能够用自己的话解释 SQL，而不仅是给出代码。

使用固定的小数据检查范围端点、模糊匹配和空值。重点区分 NULL、0、空字符串；区分 DISTINCT 对结果去重与 UNIQUE 对存储数据施加约束。

### M3：将最多的练习时间留给查询组合

这一模块是课程的主要难点，12 学时用于把简单语法组合成完整解题能力。内容按“连接 → 聚合与分组 → 子查询 → 存在性和组合条件”递进。

三表查询先画出主外键连接路径。统计题先明确统计对象是一条选课记录、一名学生还是一门课程；随后决定聚合函数、分组字段以及行条件与组条件。

存在性题单独训练：选过某课、没有选过某课、某课无人选择、同时选两门课。要求学生能解释结果集合，识别重复与遗漏，不规定所有学生只能使用同一种 SQL 写法。

关系代数与查询同步学习。通过连接、选择和投影解释已有查询，再补充集合并、交、差以及笛卡尔积的行列数量规律。文字答题必须说明参与的关系、连接依据、选择条件和投影属性。

### M4：让设计成为对已用数据库的解释与改进

先回看四表设计解决了哪些问题，再换一个场景独立设计。完整路径为：业务规则与范围 → 数据字典 → ER 模型 → 关系模式 → 规范化检查 → 类型、约束与索引等物理安排。

训练 1:1、1:N、M:N 联系的转换，以及联系属性如何进入表。特别关注带月份、借阅时间等重复业务发生条件的联合标识，防止机械地把两个外键当作所有联系表的完整主键。

规范化采用统一推理框架：列业务规则和函数依赖 → 找候选键 → 识别部分依赖或传递依赖 → 判断最高范式 → 分解并指定主外键 → 解释分解解决的异常。范式判断需要先明确原子性和函数依赖，不能仅凭某个选定主键的列数下结论。

DFD 用于说明业务中的数据流动，ER 用于说明实体及其联系，两者要能辨析。1NF—3NF 要达到解题深度，BCNF 以理解其与 3NF 的区别为主。

ER 题同时保留绘图理解与机考文字表达。文字表达至少覆盖实体、属性、标识、联系两端的基数以及联系属性。

### M5—M6：补齐实验和考试之间的缺口

视图和存储过程虽未在四个实验中被重点要求，却直接出现在综合应用题中，必须达到独立编写基本定义的程度。先完成查询，再将查询组织为视图或过程；过程还要验证调用结果。

触发器、游标、索引内部结构及并发控制以识别用途、解释差异、完成材料中的判断为主。事务则增加基本提交与回滚操作，使学生理解原子性与错误恢复。

备份部分围绕“导出 → 恢复 → 验证”组织；权限部分围绕“建立账号 → 实际连接 → 授权 → 验证允许与拒绝的操作”组织。索引同时讲查询收益和维护成本，避免背诵绝对化结论。

### M7：把已有 SQL 变成可使用的功能

项目复用已经掌握的数据库操作，保留学生、教师、课程、选课四张业务表。界面只需支持完整演示；主要评价数据操作、教师身份对应的数据范围和运行可复现性。

统一骨架应预先解决程序启动、基础界面、认证方式与连接驱动等问题。学生需要完成并解释功能对应的查询与修改逻辑；教师账号如何映射到教师工号必须清楚。

对没有编程基础的学生，骨架还应提供界面事件、输入获取、结果展示和异常处理的调用接口，预留数据库操作的位置。M7 的示范只引入完成任务所需的连接配置、参数对应和结果读取流程；学生主要填写与解释 SQL、核对参数并验证功能。若仍需从零编写这些程序基础设施，8 学时的集成安排应相应增加。

学生有编程基础时可自行选技术；没有编程基础时在统一骨架上完成数据库层和功能扩展。仅提交运行截图不足以证明完成，应能在现场更换教师或修改条件后解释和操作。

## 七、如何训练独立解题

### 1. 每类技能采用相同的学习循环

教师示范完整思路 → 学生预测结果 → 有提示练习 → 独立完成 → 换场景迁移 → 分析错误并返修。

示范时讲清为什么需要某张表、连接条件或分组字段。独立练习时撤去完整 SQL，先保留读题框架，再撤去框架。

### 2. SQL 题采用统一读题框架

1. 结果中的一行代表什么对象？
2. 要输出什么字段，分别来自哪张表？
3. 表之间按哪些键连接？
4. 哪些条件筛行，哪些条件筛组？
5. 是否涉及 NULL、重复、没有发生的记录或同时满足的条件？
6. 结果如何排序，怎样用小数据验证？

### 3. 变式题要改变需要思考的因素

变式不只替换姓名和表名，还改变输出对象、统计口径、是否保留没有记录的对象、时间范围，以及一次记录还是多次发生的业务规则。

主线场景用于建立方法；图书、销售、仓库和运动会用于检验是否理解相同结构。既训练结构迁移，也训练发现规则差异，避免看到三张表就套同一答案。

### 4. 按错误原因补练

| 错因                         | 需要的补练                                           |
| ---------------------------- | ---------------------------------------------------- |
| 读错题意或输出对象           | 先用中文写目标结果，并用小表手工列答案               |
| 找错表或连接条件             | 重画实体与键的连接路径，检查遗漏和重复               |
| 统计口径错误                 | 先说明统计单位，比较行数、非空值数、不同对象数       |
| 范式只会背定义               | 先列业务规则与函数依赖，再找候选键和异常             |
| SQL 拼写、标点与对象定义错误 | 独立输入并执行短语句，核对错误信息后重写             |
| 工具、导入恢复或权限失败     | 按执行位置、连接身份、当前库、文件与对象依赖逐项定位 |

## 八、阶段达标与考核设计

设置五个检查点，均放在对应模块学时内。下面的阈值是教学诊断建议，不替代学校既定的成绩制度。

| 检查点        | 位置      | 独立任务                             | 建议达标条件                                                                     |
| ------------- | --------- | ------------------------------------ | -------------------------------------------------------------------------------- |
| G1 基础操作   | M1 末     | 建一张含主外键的表，完成增删改并验证 | 核心约束与操作范围全部正确                                                       |
| G2 查询       | M3 末     | 混合单表、连接、统计与不存在题       | 总正确率至少 80%，四类能力均有正确任务                                           |
| G3 设计       | M4 末     | 三类设计任务各一题                   | 总分至少 70%，每类至少取得该类分值的 60%，且核心实体联系、键与范式依据无根本错误 |
| G4 管理与应用 | M6、M7 末 | 恢复验证、权限验证、项目功能演示     | 四实验要求的核心操作与功能全部完成                                               |
| G5 机考迁移   | M8        | 陌生场景的 90 分钟同结构试卷         | 至少 70 分，设计题与综合题分别至少取得其分值的 60%                               |

未达标学生进入对应能力族的补练与重测，不能只反复抄同一道题的答案。班级若出现集中错误，优先调整模块内练习和讲解时间。

建议课程成绩由过程学习 20%、四个实验 30%、期末机考 50% 构成。过程学习评价独立短练习、设计推演和错题返修；实验一、二、三、四分别占课程总成绩的 10%、8%、5%、7%。各实验先按原要求评定百分制成绩，再换算权重。

期末保持材料规定的卷面结构：单选 20 分、判断 15 分、设计 15 分、综合应用 50 分。建议学生练习的 90 分钟分配为：客观题 15 分钟、设计题 20 分钟、综合应用 45 分钟、检查 10 分钟，随后依据模拟表现调整。

过程评价允许提示与查阅，独立短测和模拟机考按考试允许的工具条件执行。机考题按语义、完整性与理由评分，允许等价 SQL 和合理的设计方案。

## 九、重点、深度与分层支持

| 层级           | 内容                                                                                     | 时间安排原则                               |
| -------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------ |
| 必须独立完成   | 建表约束、增删改、核心查询、ER 与转表、1NF—3NF、视图与基本过程、备份授权、实验四全部功能 | 保证讲解、练习与个人验证                   |
| 必须理解与辨析 | 系统概念、三层模式、关系代数基础、索引、ACID、锁、触发器、游标、BCNF                     | 用例子建立判断依据，避免长期停留在名词记忆 |
| 选学拓展       | 窗口函数、复杂过程编程、查询计划深度分析、复杂规范化证明、复制与分布式数据库             | 不占用核心能力的必要学时                   |

基础薄弱学生使用固定小数据、读题框架和中间结果提示，最终通过独立任务达标。一般学生增加混合题和陌生场景。进展较快的学生比较等价 SQL、解释结果差异并扩展项目，不要求全班同步完成拓展内容。

不要在课程开头集中讲完大段抽象理论后才开始 SQL；也不要只依照五套综合题的参考答案练习。理论应在操作、设计和错误解释中反复使用。

## 十、授课前应统一的材料口径

以下是原材料中的具体衔接或答案问题，以及建议的处理方式。本设计没有修改原始文件；后续备课时应先确定统一口径。

| 问题位置                    | 核查结果                                                                                | 建议处理                                                                   |
| --------------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 实验一与 p1data.sql         | 实验要求个人库名 `teachingdb_***`，数据脚本第一行指定 `teachingdb_chen`                 | 教学版导入脚本与学生实际库名一致，先确认当前库再导入                       |
| 实验一到实验三              | 实验三要求使用实验一生成的 `Dumpteachingdb.sql`；实验一正文仅笼统要求提交数据库文件     | M1—M3 明确留存完整导出脚本，作为后续管理实验的输入                         |
| 实验三库名                  | `teachingdb` 与 `teachingdb_chen` 混用                                                  | 统一主库名和 `teachingdb2` 的用途，并同步授权对象                          |
| 实验三部分表恢复            | 只备份学生表与课程表，但课程表外键还引用教师表                                          | 保留两表备份任务，同时明确目标库中依赖父表的前置恢复安排，并检查引用完整性 |
| 实验四登录                  | 四表原定义没有教师认证字段或账号方案                                                    | 在项目骨架与设计说明中明确认证方式和教师工号映射，保留四张业务表           |
| 实验一查询条件              | 题目使用大写课程号，脚本中使用小写；专业条件写成“软件工程（机械电子）”                  | 统一课程号表示，明确专业是任选一种还是同时查询两种，不依赖未说明的比较规则 |
| 综合应用题 3、5             | 题 3 要修改 `t001`，答案却使用 `1001`；题 5 要删除 `C001` 的选课记录，答案却使用 `1001` | 以题意为准修订教师答案，练习时要求学生核对条件与影响范围                   |
| 综合应用题 4                | 购买记录要求三字段联合主键，参考建表答案遗漏购买日期                                    | 按题目业务规则统一联合主键，检查重复业务发生条件                           |
| 综合应用题 2、5 与 SQL 排版 | 学生表主键有误写为 `gid`，插入语句有 `inset` 拼写错误，并存在中文标点与弯引号           | 核对字段名、关键字和英文输入标点，教师示范使用可执行文本                   |
| 存储过程参考答案            | 多处过程定义遗漏过程名后的空参数括号                                                    | 统一为可执行的 MySQL 定义，再用于示范与评分                                |
| 商品销售类型与时间          | 题面出现 `money`；DATETIME 销售时间被直接与某一天比较                                   | 教学版明确金额使用精确小数类型；明确“当天”的时间范围，不把午夜等同全天     |
| 设计题字段名称              | 教学 ER 文字答案把班级名写成班级号；出版社题中出版社名与出版社号也出现不一致            | 图、文字、关系模式和外键引用使用一致名称                                   |
| COUNT 与概念判断            | “COUNT 是否忽略 NULL”没有区分用法；部分运算复杂度与索引适用性题表述过于绝对             | 明确用法或前提后评分；有争议条目由教师核定，不让学生记成普遍规则           |

存储过程即使没有参数也需要 `()`；`COUNT(expr)` 统计非空表达式值，`COUNT(*)` 统计行数。这两点已对照 [MySQL 存储过程定义](https://dev.mysql.com/doc/refman/8.4/en/create-procedure.html) 与 [聚合函数文档](https://dev.mysql.com/doc/refman/8.4/en/aggregate-functions.html) 核验。

金额类型可采用 `DECIMAL`，其精确值用途见 [MySQL 定点数文档](https://dev.mysql.com/doc/refman/8.4/en/fixed-point-types.html)。授课前固定机房使用的 MySQL、Workbench、字符集与 SQL 模式，并实际检查 CHECK、外键、过程及恢复行为；CHECK 的执行语义参考 [MySQL CHECK 文档](https://dev.mysql.com/doc/refman/8.4/en/create-table-check-constraints.html)。这里引用 8.4 文档作为核验依据，不假定机房已经使用该版本。

原始数据共有学生 12 条、教师 10 条、课程 10 条、选课 24 条，包含空专业、空授课教师、空成绩，以及没有选课的学生和没有被选修的课程。可将这一数据集作为核心练习基线；每次变式或重测前说明数据状态。

## 十一、后续备课需要准备的资源

1. **统一环境说明**：版本、连接方式、账户、当前库、终端与 SQL 编辑器的使用位置。
2. **统一四表图与数据字典**：学生能独立理解表和联系，不依赖口头解释。
3. **可重置的数据基线**：原数据、练习变式数据，以及实验前后状态说明。
4. **按能力族组织的练习**：示例、有提示练习、独立练习、迁移题与重测题。
5. **经过核对的教师答案与评分依据**：包含结果语义、常见错因、等价 SQL 和合理设计分支。
6. **四实验验收标准与提交模板**：沿用现有要求，补充可验证的操作与解释证据。
7. **实验四最小项目骨架**：供缺少编程基础的学生接入已学数据库操作。
8. **两套 90 分钟模拟与反馈表**：保持正式题型比例，使用同类陌生场景检验迁移。

这些是后续教学资源的范围定义；本方案停留在课程结构、能力路径、实验安排和评价设计层面。

## 十二、学时变化时的调整

以 64 学时方案为主。若总量变为 48 学时，可采用 M0—M8 分别为 2、5、5、10、8、4、5、5、4 学时的压缩分配，合计 48 学时。

48 学时方案以预先配置环境、提供统一项目骨架为必要条件；视图和过程保留基本写作要求，管理模块聚焦原实验任务，项目模块聚焦核心功能集成。M8 进行一次 90 分钟模拟，另一次作为课后自测，保留查询、设计和四实验的核心验收。

若增加到 80 学时，优先把额外 16 学时分配给查询独立练习与补练 6 学时、设计迁移 4 学时、项目集成与个人验收 6 学时。若确认全班没有编程基础且不能提供骨架，应增加编程先修支持或调整实验四的完成方式。
