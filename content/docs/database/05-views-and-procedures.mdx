# 视图、存储过程与高级对象

在数据库应用与复杂查询场景中，**视图（View）与存储过程（Stored Procedure）**扮演着模块化封装与性能优化的关键角色。

本节我们将深入讲解视图的原理与更新限制、存储过程的严格语法标准与调用测试，并对触发器和游标等高级对象进行清晰的概念辨析。

---

## 一、视图（VIEW）：虚表的定义与安全隔离

### 1. 视图的本质与作用

- **本质**：视图是一张**虚拟表（Virtual Table）**。数据库中并不实际为视图开辟数据存储空间（不存物理元组），它仅在数据字典中保存一段 `SELECT` 查询定义。每当查询视图时，DBMS 会将视图定义与外部查询合并执行。
- **三大核心价值**：
  1. **简化复杂查询**：将复杂的三表连接、分组统计预先封装为视图，后续业务只需像查普通表一样查询该视图。
  2. **细粒度数据安全控制**：对外隐藏敏感列（如隐藏教师薪资、学生身份证号），仅将非敏感列暴露在视图中并授予只读权限。
  3. **增强逻辑数据独立性**：底层物理表结构调整时，只要适度调整视图的映射 SQL，上层依赖视图的应用程序代码可保持不变。

### 2. 视图的创建与使用语法

```sql
-- 语法：CREATE VIEW 视图名 [(列名1, 列名2...)] AS SELECT 查询语句;

-- 实例 1：创建一个查询“软件工程”专业学生的视图
CREATE OR REPLACE VIEW v_se_students AS
SELECT sid, sname, sex, age
FROM t_student
WHERE major = '软件工程';

-- 查询视图（与查询基表完全一致）
SELECT * FROM v_se_students WHERE age > 25;

-- 实例 2：创建各专业平均年龄统计视图（封装聚合计算）
CREATE OR REPLACE VIEW v_dept_avg_age AS
SELECT major, COUNT(*) AS student_count, AVG(age) AS avg_age
FROM t_student
GROUP BY major;
```

### 3. 视图的可更新性限制（机考与生产高频考点）

试图对视图执行 `UPDATE`, `INSERT`, `DELETE` 时，MySQL 必须能够明确反向追踪到唯一对应的物理基表行。如果视图定义中包含以下任何一项，则该视图**绝对不可更新（Updatable View）**：

- 包含聚合函数（`SUM`, `AVG`, `COUNT`, `MAX`, `MIN`）；
- 包含 `GROUP BY` 或 `HAVING` 子句；
- 包含 `DISTINCT` 关键字；
- 包含 `UNION` 或 `UNION ALL`；
- 涉及不可更新的视图衍生。

## 二、存储过程（STORED PROCEDURE）：语法规范与参数

存储过程是保存在数据库中的一段经过编译的 SQL 语句集合。

### 1. 规范口径：空参数也必须带有括号 `()`

依据 [MySQL 官方存储过程语法规范](https://dev.mysql.com/doc/refman/8.4/en/create-procedure.html)，以及课程第十节强调的**统一材料口径**：

> `CREATE PROCEDURE sp_name ( [proc_parameter[,...]] )`
> **即使存储过程不接受任何参数，过程名称之后也必须书写空括号 `()`**！题库早期参考答案曾出现遗漏括号的情况，在正式执行与机考书写时必须带上 `()`，否则在 MySQL 8.x 中将直接报语法错误！

### 2. DELIMITER 分隔符切换的理由

在命令行客户端中，默认以半角分号 `;` 作为单条 SQL 结束的标志。但存储过程的内部语句块（`BEGIN ... END`）包含多条以分号结尾的语句。为了防止客户端误将内部的分号当成整段过程的结束，必须临时切换分隔符（如改为 `//` 或 `$$`）：

```sql
DELIMITER //

-- 创建一个不带参数的存储过程：更新并输出选课人数超过 5 人的课程
CREATE PROCEDURE sp_get_popular_courses()
BEGIN
  SELECT c.cid, c.cname, COUNT(sc.sid) AS student_count
  FROM t_course c
  JOIN t_student_course sc ON c.cid = sc.cid
  GROUP BY c.cid, c.cname
  HAVING COUNT(sc.sid) > 5;
END //

DELIMITER ;

-- 调用执行存储过程
CALL sp_get_popular_courses();
```

### 3. 参数模式：IN、OUT 与 INOUT 实战

- **IN 参数（默认）**：入参，外部传入供过程内部读取，内部修改不影响外部。
- **OUT 参数**：出参，过程内部计算后回传给调用方。
- **INOUT 参数**：既作入参又作出参。

```sql
DELIMITER //

-- 编写带参数的过程：传入学号（IN），返回该学生已选课程的门数（OUT）
CREATE PROCEDURE sp_count_student_courses(
  IN p_sid VARCHAR(20),
  OUT p_count INT
)
BEGIN
  SELECT COUNT(*) INTO p_count
  FROM t_student_course
  WHERE sid = p_sid;
END //

DELIMITER ;

-- 测试与验证出参：
-- 1. 定义会话变量接收结果
SET @my_count = 0;

-- 2. 调用过程，传入学号 '2012001'
CALL sp_count_student_courses('2012001', @my_count);

-- 3. 查验返回结果
SELECT @my_count AS '选课门数';
```

## 三、触发器（TRIGGER）与游标（CURSOR）概念辨析

在机考概念题与单选/判断题中，经常考察触发器与游标的作用与应用场景：

| 数据库对象              | 触发机制 / 使用方式                                   | 处理粒度               | 核心用途与典型场景                                                |
| ----------------------- | ----------------------------------------------------- | ---------------------- | ----------------------------------------------------------------- |
| **触发器 (Trigger)**    | 事件驱动（由 `INSERT/UPDATE/DELETE` 隐式自动触发）    | 行级（`FOR EACH ROW`） | 记录审计日志（记录谁何时修改了成绩）、级联同步复杂业务约束        |
| **游标 (Cursor)**       | 在存储过程或函数中由代码显式声明、打开、获取和关闭    | 逐行扫描（Row-by-Row） | 当集合运算无法处理复杂的逐行迭代计算或循环审批时使用              |
| **存储函数 (Function)** | 在 SQL 表达式中直接被调用（如 `SELECT my_func(col)`） | 返回单一值             | 纯计算逻辑，必须包含 `DETERMINISTIC` 等特性声明，不能执行事务提交 |

> [!NOTE]
> **生产架构建议**
> 触发器隐式执行，排查问题隐蔽且在高并发时容易导致行锁竞争加剧；游标逐行处理性能较差。现代企业级开发提倡“轻数据库、重应用层”，复杂业务尽量由应用服务层代码处理，但在需要强数据一致性审计或题库考核时，必须准确掌握其工作机制。

## 机考真题实训：综合应用题中的对象编写

**真题模拟任务**：在教学数据库中，完成以下两道机考题目：

1. 创建视图 `v_student_grades`，包含学号、姓名、课程名和成绩四列。
2. 创建存储过程 `sp_avg_grade_by_course`，输入课程号，返回该门课程的平均成绩。

**标准解答**：

```sql
-- 1. 创建多表连接视图
CREATE OR REPLACE VIEW v_student_grades AS
SELECT s.sid, s.sname, c.cname, sc.score
FROM t_student s
JOIN t_student_course sc ON s.sid = sc.sid
JOIN t_course c ON sc.cid = c.cid;

-- 2. 创建带 IN 和 OUT 参数的存储过程
DELIMITER //
CREATE PROCEDURE sp_avg_grade_by_course(
  IN in_cid VARCHAR(20),
  OUT out_avg DECIMAL(5, 2)
)
BEGIN
  SELECT AVG(score) INTO out_avg
  FROM t_student_course
  WHERE cid = in_cid;
END //
DELIMITER ;
```
