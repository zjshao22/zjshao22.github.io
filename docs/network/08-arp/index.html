第八节：已知网关 IP，怎样发出第一帧

你在宿舍打开校外网站，笔记本知道目标网站的 IP 地址，也知道自己应先把数据报交给本地网关。但链路层发送帧时，还需要一个当前链路上的目标地址。这就出现了两个不同的问题：IP 数据报最终送往哪个网络位置？第一帧先交给哪个相邻设备？

一、IP 地址和链路地址各管一段

在本节的简化 IPv4 以太网或 Wi-Fi 情境里，网卡有链路层地址，常写成 MAC 地址，例如 02:00:00:00:10:01。这串地址只作教学示例。IP 地址属于网络层；MAC 地址用于当前局域链路上的帧传送。它们不相互替代。

假设笔记本的 IPv4 地址是 192.168.10.34/24，网关在本地链路上的 IP 是 192.168.10.1，校外服务的示例目标 IP 是 203.0.113.20。203.0.113.20 属于文档示例地址段，不是真实网站。根据 /24 前缀，校外目标不在笔记本的本地地址块中，因此笔记本选网关作为下一跳。

信息这一次应写什么为什么
IP 数据报的目标 IP203.0.113.20这是最终想访问的目标。
第一跳帧的目标链路地址网关接口的 MAC 地址帧先交给本地网关，而不是直接交给远端服务。

不要把“下一跳”误当成“最终目标”：第一跳交给网关，不意味着 IP 数据报的目标地址改成网关 IP。后续路由器继续处理这份面向远端目标的数据报。

二、不知道网关 MAC 时，ARP 怎样工作

**ARP（地址解析协议）**帮助设备在本地 IPv4 链路上查询“这个 IPv4 地址对应哪个链路地址”。笔记本若没有可用记录，会在本地链路发出 ARP 请求，大意是“谁拥有 192.168.10.1？”拥有该地址的网关接口给出自己的链路地址。笔记本得到映射后，才能把面向远端服务的 IP 数据报装进发往网关的帧。

请求通常以广播方式让本地链路上的设备都能收到；符合条件的设备给出回答，回答通常直接送回请求者。得到的映射可以暂时保存在ARP 缓存，下次不必每一帧都重新询问；缓存记录会过期或更新。不同设备的具体缓存时间不必死记。

ARP 请求只在当前链路寻找下一跳的地址。笔记本不会向整个互联网广播“谁有远端网站的 MAC 地址”。路由器收到数据报并选定下一跳后，若需要，也会在它自己的当前链路上解决同样的地址问题。

笔记本要访问 203.0.113.20，网关是 192.168.10.1，且缺少 ARP 缓存。它首先要查询谁的 MAC 地址？

三、ARP 与 DNS 千万别混

两者都像“查地址”，但输入、输出和作用范围不同：

查询输入得到什么主要用在哪里
DNS网站主机名可用的 IP 地址记录为应用找到目标网络位置
ARP当前链路上下一跳的 IPv4 地址对应的链路层地址构造这一跳的链路帧

浏览器可能先通过 DNS 得到目标 IP；笔记本再决定该目标是否在本地，若不在本地就选网关；缺少网关链路地址时，才用 ARP。DNS 不是把网站内容转发到网关的设备，ARP 也不是查网站名字的工具。

四、从一份 ARP 请求读出各字段的作用

继续使用笔记本 192.168.10.34、网关 192.168.10.1 的教学情境，并假定笔记本网卡的 MAC 为 02:00:00:00:10:34。笔记本要查询网关时，ARP 请求会表达“发送者的 IP 与 MAC 是什么、希望查询哪个目标 IP”。以太网帧的目标地址通常是广播地址 ff:ff:ff:ff:ff:ff，让本地广播域内的设备都能看到查询；请求中的目标协议地址仍是特定的 192.168.10.1，不能把“广播请求”理解成“向所有设备询问其各自的 IP”。

网关若拥有 192.168.10.1，会回复自己的 MAC，例如 02:00:00:00:10:01。笔记本随后构造发给网关 MAC 的普通数据帧。若缓存已经有可用的 192.168.10.1 → 02:00:00:00:10:01 映射，就可以省去这次请求。ARP 记录会随时间过期或被更新，所以不能把某次查到的 MAC 视为永久不变。

字段或层次查询时的值作用
以太网目标 MACff:ff:ff:ff:ff:ff把请求送达本地广播域
ARP 发送者 IP192.168.10.34告知回复方请求者的 IPv4 地址
ARP 发送者 MAC02:00:00:00:10:34告知回复方请求者的链路地址
ARP 目标 IP192.168.10.1指明要寻找哪个本地 IPv4 地址

表里没有给请求中“目标 MAC”填网关的地址，因为发出请求的原因正是尚不知道它。ARP 是链路上的独立协议消息，并非把这份查询当作普通发往远端网站的 IP 数据报进行转发。

五、同网段目标与跨网段目标分别查谁

如果笔记本要联系同一链路上的 192.168.10.80/24，按教学模型先判断目标属于本地前缀，再查询 192.168.10.80 的 MAC，并把帧直接发给该接口。若联系 203.0.113.20，应查询网关 192.168.10.1 的 MAC。两种情况下 IP 数据报的目标分别仍是 .80 与 203.0.113.20，不能因为查询了网关而把最终 IP 目标改成网关。

同属一个数值前缀并不绝对证明可直接用 ARP 到达：实际校园网还可能有 VLAN 划分、客户端隔离或代理 ARP。做这类题必须给出“同一链路、按该前缀配置、没有额外隔离”的条件。IPv6 不使用 ARP，而使用邻居发现机制；本节的推演仅针对 IPv4。

练习与解析

**题 1：**笔记本第一次访问校外网站，DNS 已得到 203.0.113.20，ARP 缓存为空。它应该先 ARP 查询 203.0.113.20 吗？**答：不应该。**目标不在本地 /24 内，先按本机路由选择网关 192.168.10.1，再在当前链路查询网关 MAC。

**题 2：**网关转发这份 IP 数据报时，第二跳帧的源 MAC 仍是笔记本 MAC 吗？**答：通常不是。**网关在下一段链路构造新帧，源链路地址是该段出口接口的地址，目标链路地址是下一跳的地址；IP 数据报的最终目标仍指向远端服务。

**题 3：**有人伪造“192.168.10.1 对应另一 MAC”的 ARP 应答，潜在影响是什么？**答：**邻居可能把发往网关的帧误发给错误设备，导致中断或流量被转送。ARP 本身不认证应答来源；实际校园网络可用交换机防护、网络准入等措施降低风险。这个例子也说明缓存里的映射是当前观察结果，不等于经过密码学验证的身份。

把新增的四节连成一个过程

协议先约定字段如何编码，包括多字节数值的网络字节序；IPv4 地址和 CIDR 前缀描述目标所在的地址块；路由器用最长前缀匹配选出下一跳；设备再用 ARP 找到当前链路上下一跳的地址，发出链路帧。你已经能从“数据报里有什么”继续解释到“它为什么从这个出口走、第一帧发给谁”。
