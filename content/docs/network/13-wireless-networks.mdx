# 第十三节：Wi-Fi 为什么需要争用与重试

教室中每台电脑都显示已连接 Wi-Fi，但同时下载时吞吐下降，走到走廊又出现卡顿。若把 Wi-Fi 想成“去掉网线的全双工以太网”，这些现象就很难解释。无线终端共享空气中的传送机会，而且彼此听到的信号未必一样。

## 一、先分清 AP、交换机与路由器

**接入点 AP**组织一个无线基本服务集，使终端关联到这个无线网络，并把无线侧与分布系统连接起来。AP 可以承担二层桥接；“连接 AP”不自动等于获得 IP 地址，也不保证外网路由可达。

家用无线盒子通常把 AP、以太网交换机、IP 路由器、DHCP 服务和 NAT 集成在同一设备里。它们物理上在一个壳子中，逻辑上仍有不同职责。校园 AP 则可能由控制器集中管理，IP 默认网关在另一台设备上。

**SSID**是用户看到的网络名称；**BSSID**标识特定基本服务集，基础设施模式通常与 AP 的无线接口相关。两台 AP 可以提供相同 SSID，也可能服务不同信道；只看 SSID 无法判断终端是否已经从一个 AP 漫游到另一个。

## 二、为什么“听到空闲就发”仍会碰撞

在基础教学模型中，A、C 都能与 AP B 通信，但 A 与 C 因距离或墙壁听不到彼此。这叫**隐藏站**。A 监听时听不到 C，C 监听时听不到 A；两者可能同时发送，导致 B 接收到重叠信号而无法正确解码。

| 谁正在发送 | A 能听到吗 | B 能听到吗 | C 能听到吗 |
| ---------- | ---------- | ---------- | ---------- |
| A          | 自己发送   | 是         | 否         |
| C          | 否         | 是         | 自己发送   |

“所有人先听一下”不足以形成全局一致的空闲判断。无线发送时自己的强信号也使实时检测远端碰撞困难，因此常见 802.11 接入采用 **CSMA/CA（碰撞避免）**，而不是直接复用共享以太网的 CSMA/CD。[IEEE 的 802.11 说明](https://www.ieee802.org/11/main.html)给出了这个基本访问机制。

## 三、等待、随机退避、确认与重试

先看传统争用接入的简化过程。终端在允许的帧间间隔后，从争用窗口随机选退避计数；每经过一个合格空闲时隙计数减一。若介质忙，计数暂停；重新满足空闲条件后再继续。计数到零时才发送。

不同帧类别有不同访问参数，较新的 Wi-Fi 还引入调度与多用户传送。本页用基本争用机制说明问题，不宣称所有无线帧都遵循同一种时序。

**Wi-Fi ACK 是一段无线链路的确认，不等于 TCP ACK。**它说明无线接收端收到了这帧；没有证明远方服务器收到、TCP 字节全部有序到达，或应用处理成功。广播和某些组播传送也不采用相同的逐帧确认方式。

随机退避减少同步发送，不保证零碰撞。ACK 丢失可能导致已收数据再次发送，接收端还需根据相关序号识别重复帧。无线重试消耗额外空口时间，并可能使上层观察到时延变化。

## 四、亲手走一遍退避计数

以下是**教学时序**，忽略帧间间隔具体长度，定义“空闲时隙”是完成相关等待后可计数的时隙。A、C 初始退避值分别为 2、4；二者能听到彼此，本题不采用隐藏站条件。

| 事件                         | A 的计数   | C 的计数    |
| ---------------------------- | ---------- | ----------- |
| 初始                         | 2          | 4           |
| 经过第一个空闲时隙           | 1          | 3           |
| 经过第二个空闲时隙           | 0          | 2           |
| A 开始发送并完成交换         | 正在交换   | 冻结在 2    |
| 再满足空闲条件，经过一个时隙 | 已完成本次 | 1           |
| 再经过一个时隙               | 已完成本次 | 0，C 可发送 |

C 不是在 A 发送期间继续计数，也不一定在 A 结束后重新抽一个初始值。对照自己的计数表，说明冻结机制为什么避免多个等待者在介质一空闲时一起发送。

如果 A、C 都选 2，则仍可能同时发出。这是随机机制的概率性质；重试与窗口调整处理剩余碰撞风险。

## 五、RTS/CTS 怎样帮助隐藏站

对于第二部分的隐藏站模型，可选择先进行 **RTS/CTS** 交换：A 向 B 发短 RTS，B 回 CTS，随后 A 发数据，B 回 ACK。能听到 B 的 C 根据 CTS 中的持续时间设置虚拟载波侦听计时，在这次交换期间退让。

| 接收者 | 可能听到的控制信息 | 可以据此做什么                     |
| ------ | ------------------ | ---------------------------------- |
| B      | A 的 RTS           | 允许本次后续传送并回复 CTS         |
| C      | B 的 CTS           | 即使听不到 A，也知道这段时间需退让 |
| A      | B 的 CTS           | 知道可以继续本次数据交换           |

RTS 自己也可能碰撞；控制帧会增加开销；不同拓扑的隐藏关系不总能被完全解决。因此它是减少某些冲突损失的可选机制，**不是消灭所有无线干扰的开关**。短帧、低争用环境下，增加两份控制帧可能得不偿失。

虚拟载波侦听的计时与物理层检测到信号互相补充。收到 CTS 的 C 即使此刻没有检测到 A 的强信号，也知道不应抢占约定交换。

## 六、无线接收者未必是 IP 目的

A 要访问远方服务器，当前无线传送先从 A 到 AP；逻辑上送往本地默认网关 G，IP 目的仍为远方服务器 S。**空中这一次传送的接收者 AP、链路目的 G、IP 目的 S 可以是不同实体。**

基础设施模式 802.11 帧用多个地址字段表达这些角色，字段含义还取决于 To DS/From DS 等方向位。在常见的终端向分布系统发送、三地址模型中，可以分别表达 AP 接收者、终端发送者和逻辑链路目的。不能把普通 Ethernet II 的两地址图直接当成空中帧格式。

| 所在层或角色     | 本例对象      |
| ---------------- | ------------- |
| 无线发送者       | A 的无线接口  |
| 无线接收者       | AP 的无线接口 |
| 当前逻辑链路目的 | 默认网关 G    |
| 网络层最终目的   | 服务器 S      |

如果 AP 同时就是网关，两个角色可能由同一设备承担；这只是部署上的重合，不应抹掉它们的职责区别。

## 七、为什么显示速率不等于下载速度

无线物理速率受信道宽度、调制编码方案、空间流数量、信号质量等影响。**OFDM**把信道分成多个正交子载波来传符号；**OFDMA**进一步让调度者把资源单元分配给多个用户；**MIMO**利用多天线与空间维度。它们改善传送能力，也都需要相应的设备、信道条件与调度。

终端显示的协商速率通常是物理层某方向的传送参数，不扣除争用、等待、控制帧、首部与重试。多个终端共享空口时间，AP 上联和远方服务还可能成为瓶颈。测得 200 Mbps goodput，不意味着物理显示的 600 Mbps 必定配置错误。

一个简化空口模型：A 以 100 Mbps 发 1 Mbit，需 10 ms；B 以 20 Mbps 发同量需 50 ms。若二者轮流各发一份，且忽略额外开销，60 ms 内送达 2 Mbit，总 goodput 约 33.3 Mbps。低速终端可能消耗较长时间，但现实公平策略、速率适配与多用户机制会改变结果。

## 八、移动接入还需要哪些状态变化

同一个 SSID 下从 AP1 转向 AP2，终端需选择与新 AP 关联，相关认证与转发位置也可能更新。若服务仍处于同一网络层子网，IP 地址可以保持；跨到另一个网络则可能重新配置地址，已有传输连接能否保持取决于地址、网络与协议机制。

蜂窝网络用基站覆盖小区，运营商网络协调身份认证、无线资源与移动过程。频率复用与调度允许不同小区服务用户；越靠边缘，干扰、信号质量与切换都影响体验。蜂窝并不是把 AP 换一个名字，核心网还承担会话与移动管理。

卫星接入仍使用无线传播，但距离可能显著增加 RTT；有更高物理速率，也无法取消距离项。接入技术不同，后续 IP、传输协议与应用仍需面对时延、丢包和资源共享。

## 九、实际观察：关联、信号与时延分开记录

在自己的电脑中读取无线连接信息，记录 SSID、BSSID、信道、信号指标和协商速率；Windows 可用 `netsh wlan show interfaces`，其他系统可通过无线详情界面查看。对自己有权测试的本地网关做少量 ping，记录 RTT。

若环境允许，保持同一目标、同一设备，分别在教室内两个位置测量。先预测哪项可能变化，再记录实际值。不要把同一 SSID 当作同一 BSSID，也不要把 dBm 的负值直接当成 Mbps。

交出对照表与解释：哪些变化支持无线侧条件变化，哪些仍可能由拥塞造成？普通抓包模式未必展示管理、控制和无线重试；没有监控模式证据时，不应从一次 ping 抖动反推出准确重试次数。

### 控制开销也要占空口

另一个教学模型忽略争用，规定一次 DATA 占 1.00 ms，ACK 占 0.05 ms，每处必要等待合计 0.10 ms。基本交换一共 1.15 ms。若额外 RTS、CTS 各占 0.05 ms，新增等待共 0.10 ms，则本次无碰撞交换变成 1.35 ms。

这次增加 0.20 ms，却可能把隐藏站环境中长数据帧碰撞造成的损失，改成较短 RTS 的损失。判断“是否更划算”需要碰撞概率与重试成本，而不能只看成功一次多了两个控制帧。

<details>
<summary>核对可以得出的结论</summary>

本模型无碰撞时，额外机制降低单次净传送效率；高碰撞时，它可能减少重试浪费。给定成功一次的耗时不足以算真实长期 goodput，需要记录失败与重试等事件。

</details>

## 十、独立变式：改变可见关系

A 与 C 都能听到 AP B，但听不到彼此。C 听到了 B 回给 A 的 CTS：它该不该因为听不到 A 的数据就立刻发送？若一次数据已经被 B 收到，但 A 没收到 ACK，A 重发后是否应让上层收到两份相同数据？最后把第七部分 B 的速率改成 50 Mbps，重算忽略开销的总 goodput。

<details>
<summary>完成后核对</summary>

C 应根据相关虚拟载波侦听持续时间退让，不能只看自己此刻听到的物理信号。重传需要重复识别机制，已收的同一帧不应因 ACK 丢失而当成全新的上层数据交付。改速率后分别占 10 ms、20 ms，总 30 ms 送 2 Mbit，约 66.7 Mbps；这仍是简化模型。

</details>
