# 第三节：数据怎样穿过校园网

你在宿舍打开课程平台，或用手机流量查看一段国内视频。设备与服务端通常没有一根专用直连线；中间可能经过不同网络。**IP 的工作是让数据报朝目标网络位置前进。** 这节课不需要知道真实运营商的内部拓扑，只用一个简化网络学习转发原理。

## 一、什么是 IP 数据报

应用交给网络的内容不会单独“裸奔”。IP 把上层交来的数据放在**负载**里，在前面加上**首部**，形成 IP 数据报。首部包含源 IP 地址、目标 IP 地址等控制信息；目标地址是路由器决定下一步的重要依据。

<DatagramFigure />

IP 地址用于描述网络中的位置，不是人的姓名，也不是课件路径。比如宿舍设备可能拿到一个校内使用的地址；访问外部服务时还可能经过地址转换或代理。为了练习，下面只用 A、B 这样的代号表示目的地，**不把教学代号当成真实校园网地址**。

## 二、路由器只决定“下一跳”

设想 A 是宿舍笔记本，B 是课程平台服务器；R1、R2、R3 是路由器。R1 不必预先知道从 A 到 B 的每一段连接，只需依据自己的**转发表**决定交给哪一个相邻设备。下一台路由器再做同样的事。

先看一张只用于课堂推演的简化表：

| 路由器 | 目标 B 的下一跳 | 目标 C 的下一跳 |
| ------ | --------------- | --------------- |
| R1     | R2              | R3              |
| R2     | B               | R3              |
| R3     | R2              | C               |

目标是 B，且数据报已经到 R1：R1 查表交给 R2，R2 查表交给 B。若目标换成 C，R1 交给 R3，R3 交给 C。现实中的路由器通常按**地址前缀**匹配转发表，而不是直接用 B、C 两个字母；表格只为练习“本地决定下一跳”。

如果 R1 到 R2 的连接坏了，不能仅凭这张旧表说“一定会自动绕开”。网络需要获知故障并有新的可用转发信息。**多条可能路径不等于每次故障都能无缝恢复。**

## 三、为什么把数据分成包

宿舍里有人下载大文件，旁边有人只发一条班级群消息。如果下载者长期独占整条链路，短消息也得等到下载完成。**分组交换**让数据被拆成可独立处理的包，不同通信的包可以交替使用同一条链路。路由器逐份处理，当前出口忙时，后来到达的包可能先排队。

用一个具体队列推演：出口正在发送 A1，等待队列最多放两份；B1、A2 已在排队。这时 B2 到来，队列已满，B2 可能被丢弃。接收端看到的顺序与发送端原本的动作不一定相同，沿途排队或走不同路径都可能造成差异。

分组交换提高了链路共享的灵活性，但并不承诺“无等待、无丢包”。网络繁忙时，排队使响应变慢；缓冲区放不下时，包可能丢失。这也解释了为什么“视频转圈”可以与“设备已经连上 Wi-Fi”同时发生：接入成功只是一个环节，后续的服务和网络状态仍可能影响体验。这里不能仅凭转圈就断定具体是哪一段出了问题。

## 四、IP 的承诺有多大

IP 提供**尽力而为的数据报服务**：网络会尝试把每份数据报送向目标，但协议本身不保证它一定到达、不重复、按顺序到达，或在某个时限内到达。IP 转发也不要求先为一组数据报建立一条专用电路，所以称为**无连接**。

“不可靠”在这里是严格的技术用语，意思是**IP 不作交付保证**，不是说校园网平时一定坏。需要完整、按序内容的应用可以借助 TCP 等上层机制检测丢失并重传；对实时性的取舍可能不同。**IP 负责尽力转发，是否补救由上层服务与应用决定。**
