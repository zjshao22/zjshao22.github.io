# 15｜指令微调与对话格式

续写模型看到“请把这句话翻译成英文”，可能继续编一个类似问题，而不是回答。预训练擅长预测文本，助手却需要遵守任务和对话结构。指令微调用请求及合适回答作示范，让模型提高这些回答在对应上下文中的概率。

## 提示和微调改变哪里

提示在本次输入里加入要求，权重不变；监督微调把许多请求—回答样本用于训练，权重发生更新。二者都可能影响行为，但不能把“换提示后答对”写成“模型已经微调”。微调也不是把所有新资料当数据库可靠存入参数；频繁变化的校规仍更适合检索。

给定课程构造样本：用户“把 12 分钟换成秒”；示范回答“12×60=720 秒”。训练时需要确定哪些词元计算损失。一个常见做法是把整段对话送入模型，但只在助手回答位置计损失，问题位置用于提供条件。

| 位置内容           | 角色     | 可进入上下文 | 本例是否计回答损失 |
| ------------------ | -------- | ------------ | ------------------ |
| “你是单位换算助手” | 系统约束 | 是           | 否                 |
| “把 12 分钟换成秒” | 用户请求 | 是           | 否                 |
| “12×60=720 秒”     | 助手示范 | 逐步因果读取 | 是                 |
| 结束标记           | 助手终止 | 是           | 是                 |

若把用户段错误标为助手答案，就改变了角色与训练目标；全序列损失也可以是另一种合法配方，但须明确记录，不能与本例的 assistant-only 目标混称；若目标位置偏移错了，还可能偷看答案。不同训练配方可有不同掩码，本课应记录选择，而非宣称唯一合法方式。

## 对话模板为什么影响结果

模型读取的是词元，不是界面里彩色聊天气泡。角色分隔、消息结束、助手起始等需要被序列化成与训练匹配的格式。模板错配会使模型误以为仍在用户文本中，或把控制标记当正文继续。用户输入中出现“system”字样，也不应由执行器直接升级为高权限消息。

设两类输出为正确换算与复述问题，初始概率 $(0.4,0.6)$，示范选择前者，交叉熵为 $-\ln0.4\approx0.9163$，得分梯度为 $(-0.6,0.6)$。反向传播通过输出层、隐藏层与嵌入提高合适回答的概率。和下一词元训练相比，数学工具并未换掉，主要变化是数据分布、格式与目标位置。

## 好示范也需要覆盖失败条件

如果所有示例都有答案，助手可能被鼓励在资料不足时也作答。加入“给定材料无法确定”的示范、冲突材料处理和澄清问题，可以教更合适的行为。但示范需要正确；把算错的标准答案批量加入，会使模型更稳定地犯错。还要留出不同数字、问法和组合单位，避免只记模板。

本课无 GPU 和云 API。微型监督训练在 [L3](/docs/ai/lab-03-feedback-and-budget) 的 `practice.py sft` 中实际执行：仅回答位置计损失，保存掩码、参数与概率更新。它从随机初始化的微型 Transformer 开始，不冒称通用预训练模型微调。通用助手 CPU 运行另有本地选配路径，需要已有合法权重和匹配运行时，速度以机器实测为准。

## 学生任务：标出损失位置

构造两轮对话：用户“3 小时是多少分钟”，助手“180 分钟”；用户“那再加 20 分钟”，助手“200 分钟”。将它序列化成角色清楚的文本，指出第二轮回答依赖哪里，并设计两个不参与训练的测试。

## 独立变式

模型微调后更严格输出 JSON，但事实错误率没变，这算成功吗？

<details>
<summary>独立完成后核对</summary>

若目标包含格式，则格式指标改善；若目标是可靠问答，仍未完成。应分开报告语法有效率、字段完整率、事实支持率，不能由格式合格推导内容可靠，也不能忽略已经发生的局部改善。

</details>
