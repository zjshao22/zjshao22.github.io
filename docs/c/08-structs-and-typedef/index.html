结构体、枚举与自定义类型

在前面的学习中，我们处理的数据都是基本类型（整数、浮点数、字符）或者它们的同质集合（数组）。然而，在现实世界中，一个业务对象往往是由不同类型的数据项共同组成的：例如一名学生，既有整型的学号，又有字符数组的姓名，还有浮点型的成绩。

结构体（struct） 赋予了程序员根据实际需求将不同数据类型聚合为一个全新复合类型的能力。

本节全面解析结构体定义与内存布局、成员访问运算符（. 与 ->）、底层字节对齐与空间填充规则，以及 typedef 类型别名与 enum 枚举的应用。

为什么 (*p).id 必须加圆括号？

因为在 C 语言运算符优先级表中，点运算符 . 的优先级为最高级（1级），而解引用运算符 * 仅为 2 级！如果不加括号写成 *p.id，会被编译器理解为 *(p.id)，引发语法报错！使用 p->id 则兼顾了安全与优雅。

三、结构体内存字节对齐与 sizeof 真实大小

许多初学者理所当然地认为：结构体占用的内存大小等于所有成员大小的简单累加。这是完全错误的！

为了提高 CPU 通过数据总线读取物理内存的吞吐效率，现代编译器会遵循内存字节对齐（Byte Alignment） 规则：

结构体对齐核心规则（基于主流自然对齐 ABI）

在未指定 #pragma pack 打包指令的主流平台（x86-64 / ARM64）ABI 规范下，结构体布局遵循类型的对齐要求（Alignment Requirement，C11 中可用 _Alignof 获取），而非简单看成员的 sizeof：

  1. 成员对齐：每个成员的起始偏移量（Offset），必须是其类型对齐值的整数倍。若前一个成员结束后空位不满足对齐要求，编译器会自动填充 Padding 字节。 (注：数组成员的对齐值等于其基元素类型的对齐值，例如 char bytes[3] 的对齐要求是 1 字节，而不是 3 字节)。
  2. 总大小对齐：整个结构体的总字节大小，必须是结构体中最大成员对齐值的整数倍。末尾不足时同样会填充 Padding，以保证该结构体构成数组时，后续每个元素都能满足对齐要求。

成员本身只占 1+4+2=71 + 4 + 2 = 71+4+2=7 字节，但在默认 4 字节自然对齐前提下，通过 sizeof(struct Example) 计算出来的真实大小是 12 字节！

五、枚举类型：enum

枚举（enum） 是一组具名的整型常量集合，常用于表达有限的状态、方向或选项：

关键概念：C 语言枚举的底层本质是整数

在 C 语言中，枚举在底层兼容某种整数类型（通常为 int）。语言机制本身并不会在编译或运行时强制阻止将列表之外的整数赋值给枚举变量（例如写 today = 99; 在 C 语言语法中是合法的）。枚举的核心价值在于为代码赋予清晰的符号常量和有限状态意图；若业务要求严格限定输入值，需要开发者显式编写校验逻辑。

本节小结与核心要点

  1. 类型定义不占内存：声明 struct 模板不分配空间，定义具体变量才分配。
  2. 两类访问运算符：普通变量用点 .，指针变量用箭头 ->（p->id ≡ (*p).id）。
  3. 内存对齐防空洞：成员偏移与总大小均须对齐，sizeof 通常大于各成员简单累加之和。
  4. typedef 只是取别名：不创建新类型，只为已有类型提供简明名称。
  5. enum 是整数符号集合：默认从 0 开始递增，增强程序语义可读性。
