第二节：互联网的四层模型

上一节看到应用希望交换数据，却没有解释：数据怎样从一台主机到另一台？如果浏览器必须自己研究 Wi-Fi、光纤和每台路由器，就很难写出通用软件。互联网用分层把任务拆开：每一层向上一层提供一种服务，使用下一层的服务完成自己的工作。

四层各回答一个问题

层主要问题常见例子
应用层这些字节代表什么请求或内容？HTTP、文件共享应用
传输层数据交给目标主机上的哪个程序？需要怎样的端到端传输？TCP、UDP、端口
网络层数据怎样跨越多个网络到达目标主机？IP 地址、IP 数据报、路由器
链路层数据怎样通过当前这一段连接？Wi-Fi、以太网

例如你的电脑通过 Wi-Fi 接入，服务器通过以太网接入。两端使用的链路技术不同，但都能在网络层使用 IP。IP 就像众多链路技术和上层服务之间的共同接口，原讲义称它为互联网的 “细腰”（thin waist）：下面可以有不同链路，上面可以有不同传输和应用。

分层带来了什么

分层首先让系统可替换：一家学校升级无线网络，不需要因此重写所有网页程序。它还让系统可复用：同一套 IP 转发能力可以服务网页、文件传输和其他应用。最后，它让问题更容易定位：页面路径错误与 Wi-Fi 断开是不同层次的问题，检查办法也不同。

这并不是说各层完全互不影响。链路拥堵会让上层感觉变慢；传输协议的选择也会影响应用表现。分层的意思是明确接口和责任，不是假装别的层不存在。

不要把这四个问题合成一个问题
网页路径 /article应用要哪个资源
端口 443目标主机的哪个服务端点
目标 IP 地址把数据送往哪个网络位置
当前 Wi-Fi 链路先把数据交给相邻设备

沿着一份数据向下看

浏览器创建请求 → 传输层把数据组织成可传输的单位 → 网络层把它放进 IP 数据报，并写上目标 IP 地址 → 链路层让数据越过第一段连接。路由器收到后，查看网络层的信息并决定下一跳，再用下一段链路发送。每一跳的链路可能变，IP 数据报仍指向终点。 传输层的端到端处理主要发生在通信主机，普通转发路由器不需要理解网页正文。

看一个具体的交付边界：你的笔记本同时开着浏览器和聊天程序。目标 IP 地址让数据来到这台笔记本；端口等传输层信息帮助系统区分要交给哪个通信端点。反过来，路由器在途中转发时，最关心的是数据报下一步该去哪里，而不是你打开的是文章还是聊天窗口。

为什么 IP 不保证一切？

IP 的主要工作是尽力交付数据报。数据报可能丢失、重复或乱序。需要可靠有序字节流的应用，可以在 IP 之上使用 TCP；对延迟和消息边界有不同需求的应用，也可以选其他传输方式。这样，网络层不必为所有应用固定一种“可靠”的定义。

电脑从 Wi-Fi 切换到有线以太网后，四层模型最直接体现了什么好处？

自己给任务归位

把下面四句话分别放到一层，并说明为什么是这一层的任务：

  • “把数据交给本机监听某个端口的程序。”
  • “根据目标 IP 地址查询转发表，选择下一跳。”
  • “在本地无线网络上传送一帧。”
  • “解释 GET /article 是请求什么资源。”

提示：同一件完整的网络通信要经过多层，但每句话的直接责任只有一个。完成后，再用“上层使用下层提供的服务”解释一次网页访问。
