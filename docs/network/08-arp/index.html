第八节：已知网关 IP，怎样发出第一帧

你在宿舍打开校外网站，笔记本知道目标网站的 IP 地址，也知道自己应先把数据报交给本地网关。但链路层发送帧时，还需要一个当前链路上的目标地址。这就出现了两个不同的问题：IP 数据报最终送往哪个网络位置？承载它的第一跳数据帧先交给哪个相邻设备？

一、IP 地址和链路地址各管一段

本节采用简化的 IPv4 以太网逻辑链路模型：讨论以太网帧的源、目标 MAC 地址，假设本地设备间没有额外隔离。网卡有链路层地址，常写成 MAC 地址，例如 02:00:00:00:10:01。这串地址只作教学示例。IP 地址属于网络层；MAC 地址用于当前局域链路上的帧传送。它们不相互替代。

宿舍实际可能通过 Wi-Fi 接入，但无线链路上的 802.11 帧还有接收者、发送者等地址字段。笔记本向网络上行发送时，直接接收无线帧的可以是接入点 AP，而需要交付的目标仍可能是网关；AP 与网关也不一定是同一个设备。因此下面的以太网目标 MAC，不能直接当作 Wi-Fi 帧所有地址字段的答案。

假设笔记本的 IPv4 地址是 192.168.10.34/24，网关在本地链路上的 IP 是192.168.10.1，校外服务的示例目标 IP 是203.0.113.20。203.0.113.20 属于文档示例地址段，不是真实网站。根据 /24 前缀，校外目标不在笔记本的本地地址块中，因此笔记本选网关作为下一跳。

信息这一次应写什么为什么
IP 数据报的目标 IP203.0.113.20这是最终想访问的目标。
第一跳以太网数据帧的目标 MAC网关接口的 MAC 地址数据帧先交给本地网关，而不是直接交给远端服务。

不要把“下一跳”误当成“最终目标”：第一跳交给网关，不意味着 IP 数据报的目标地址改成网关 IP。后续路由器继续处理这份面向远端目标的数据报。若缺少网关的地址映射，时间顺序上先发出的可能是 ARP 广播请求帧；“数据帧发给网关”指承载 IP 数据报的帧，不是说所有先发出的帧都使用网关 MAC。

二、不知道网关 MAC 时，ARP 怎样工作

ARP（地址解析协议） 帮助设备在本地 IPv4 链路上查询“这个 IPv4 地址对应哪个链路地址”。笔记本若没有可用记录，会在本地链路发出 ARP 请求，大意是“谁拥有 192.168.10.1？”拥有该地址的网关接口给出自己的链路地址。笔记本得到映射后，才能把面向远端服务的 IP 数据报装进发往网关的帧。

请求通常以广播方式让本地链路上的设备都能收到；符合条件的设备给出回答，回答通常直接送回请求者。得到的映射可以暂时保存在ARP 缓存，下次不必每一帧都重新询问；缓存记录会过期或更新。不同设备的具体缓存时间不必死记。

ARP 请求只在当前链路寻找下一跳的地址。笔记本不会向整个互联网广播“谁有远端网站的 MAC 地址”。路由器收到数据报并选定下一跳后，若需要，也会在它自己的当前链路上解决同样的地址问题。

笔记本要访问 203.0.113.20，网关是 192.168.10.1，且缺少 ARP 缓存。它首先要查询谁的 MAC 地址？

三、ARP 与 DNS 千万别混

两者都像“查地址”，但输入、输出和作用范围不同：

查询输入得到什么主要用在哪里
DNS网站主机名可用的 IP 地址记录为应用找到目标网络位置
ARP当前链路上下一跳的 IPv4 地址对应的链路层地址构造这一跳的链路帧

浏览器可能先通过 DNS 得到目标 IP；笔记本再决定该目标是否在本地，若不在本地就选网关；缺少网关链路地址时，才用 ARP。DNS 不是把网站内容转发到网关的设备，ARP 也不是查网站名字的工具。

在本节以太网模型中，关于发往校外服务的第一跳数据帧，哪句话准确？

四、从一份 ARP 请求读出各字段的作用

继续使用笔记本 192.168.10.34、网关192.168.10.1的教学情境，并假定笔记本网卡的 MAC 为02:00:00:00:10:34。笔记本要查询网关时，ARP 请求会表达“发送者的 IP 与 MAC 是什么、希望查询哪个目标 IP”。以太网帧的目标地址通常是广播地址ff:ff:ff:ff:ff:ff，让本地广播域内的设备都能看到查询；请求中的目标协议地址仍是特定的192.168.10.1，不能把“广播请求”理解成“向所有设备询问其各自的 IP”。

网关若拥有 192.168.10.1，会回复自己的 MAC，例如 02:00:00:00:10:01。笔记本随后构造发给网关 MAC 的普通数据帧。若缓存已经有可用的 192.168.10.1 → 02:00:00:00:10:01 映射，就可以省去这次请求。ARP 记录会随时间过期或被更新，所以不能把某次查到的 MAC 视为永久不变。

字段或层次查询时的值作用
以太网目标 MACff:ff:ff:ff:ff:ff把请求送达本地广播域
ARP 发送者 IP192.168.10.34告知回复方请求者的 IPv4 地址
ARP 发送者 MAC02:00:00:00:10:34告知回复方请求者的链路地址
ARP 目标 IP192.168.10.1指明要寻找哪个本地 IPv4 地址

表里没有给请求中“目标 MAC”填网关的地址，因为发出请求的原因正是尚不知道它。ARP 是链路上的独立协议消息，并非把这份查询当作普通发往远端网站的 IP 数据报进行转发。

五、同网段目标与跨网段目标分别查谁

如果笔记本要联系同一链路上的 192.168.10.80/24，按教学模型先判断目标属于本地前缀，再查询192.168.10.80的 MAC，并把帧直接发给该接口。若联系203.0.113.20，应查询网关192.168.10.1 的 MAC。两种情况下 IP 数据报的目标分别仍是 .80 与 203.0.113.20，不能因为查询了网关而把最终 IP 目标改成网关。

同属一个数值前缀并不绝对证明可直接用 ARP 到达：实际校园网还可能有 VLAN 划分、客户端隔离或代理 ARP。做这类题必须给出“同一链路、按该前缀配置、没有额外隔离”的条件。IPv6 不使用 ARP，而使用邻居发现机制；本节的推演仅针对 IPv4。

练习与解析

题 1：笔记本第一次访问校外网站，DNS 已得到 203.0.113.20，ARP 缓存为空。它应该先 ARP 查询 203.0.113.20 吗？

查看题 1 解析

不应该。目标不在本地 /24 内，先按本机路由选择网关 192.168.10.1，再在当前链路查询网关 MAC。

题 2：网关转发这份 IP 数据报时，假设下一段也是以太网链路，第二跳数据帧的源 MAC 仍是笔记本 MAC 吗？

查看题 2 解析

不是。网关在下一段以太网链路构造新帧，源 MAC 是该段出口接口的地址，目标 MAC 是下一跳的地址；在这里没有地址转换的教学模型中，IP 数据报的最终目标仍指向远端服务。

题 3：有人伪造“192.168.10.1 对应另一 MAC”的 ARP 应答，潜在影响是什么？

查看题 3 解析

邻居可能把发往网关的帧误发给错误设备，导致中断或流量被转送。ARP 本身不认证应答来源；实际校园网络可用交换机防护、网络准入等措施降低风险。这个例子也说明缓存里的映射是当前观察结果，不等于经过密码学验证的身份。

六、动手推演：从离线记录还原第一跳

这份记录可直接在纸上分析，不需要安装抓包工具。笔记本为 192.168.10.34/24，MAC 为 02:00:00:00:10:34，唯一默认网关为 192.168.10.1。采用前面的以太网模型，192.168.10.0/24 内的设备在同一本地链路，无其他路由、地址转换或隔离。开始时缓存里只有有效记录 192.168.10.80 → 02:00:00:00:10:80，没有网关记录。

笔记本接下来向 203.0.113.20 连续发送两份 IP 数据报。下面完整列出这次教学过程中的 ARP 与数据帧；只关注地址字段，不计算首部长度。

先计算远端目标是否属于 192.168.10.0/24，再写出下一跳 IP；逐行解释谁在查询、谁在应答、数据帧交给谁；最后说明为什么 6 ms 前没有再次出现 ARP 请求。交出一张四行时序说明和应答后的缓存表。验证时分别核对“ARP 查询目标是否等于下一跳 IP”和“数据帧目标 MAC 是否来自该映射”，再确认两份 IP 数据报的目标一直是远端地址。

还不知道该查谁：先确定下一跳

把笔记本的 /24 前缀与目标比较。缓存里有 .80 的映射，只说明知道 .80 的链路地址；要先判断这次数据报是否需要交给 .80，不能拿任意已有记录来发帧。

已经确定下一跳：再区分两类帧

ARP 请求要寻找下一跳的 MAC，可用本地广播发出查询；普通数据帧使用查询得到的地址。分别写这两类帧的目标 MAC，并把 IP 数据报的目标另列一栏，避免把三者混为一谈。

完成后核对时序与缓存

203.0.113.20 不属于 192.168.10.0/24，下一跳是 192.168.10.1。0 ms 的广播请求查询该网关；3 ms 的应答给出 .1 → 02:00:00:00:10:01；4 ms 与 6 ms 的数据帧均交给这一 MAC，其中的 IP 目标均为 203.0.113.20。

缓存中的 IPv4 地址MAC 地址
192.168.10.8002:00:00:00:10:80
192.168.10.102:00:00:00:10:01

假定刚学到的网关记录在 6 ms 时仍有效，第二份数据报可复用它。最早出现的帧是发往广播 MAC 的 ARP 请求，第一份承载 IP 数据报的数据帧才发往网关 MAC。ARP 应答解决地址映射，不能单凭这四行断言远端服务已收到数据或已返回网页。

换一个条件：目标改为本地设备，缓存过期

目标改为 192.168.10.80，其他网络条件相同；但发送前唯一的 .80 缓存记录已过期，应视为不可用。假定 .80 收到查询后回答自己的 MAC 为 02:00:00:00:10:80。依次写出下一跳 IP、ARP 请求中的查询目标、请求帧目标 MAC、收到应答后数据帧的目标 MAC，以及数据报的目标 IP。能否因为网关一直可用就只查网关？

查看迁移题解析

.80 在 192.168.10.0/24 内，且题设明确同一本地链路、没有隔离，所以直接交付：下一跳 IP 为 192.168.10.80。缓存已过期，需要查询 192.168.10.80；以太网 ARP 请求帧的目标为 ff:ff:ff:ff:ff:ff。应答后数据帧目标 MAC 为 02:00:00:00:10:80，其中数据报的目标 IP 仍为 192.168.10.80。

查询网关只会得到网关的 MAC，无法代替本次对本地目标的直接交付。若只把缓存条件改回“.80 记录仍有效”，则无需发 ARP 请求，可直接使用 .80 的映射；IP 目标与下一跳都不因此改变。

把地址与转发连成一个过程

协议先约定字段如何编码，包括多字节数值的网络字节序；IPv4 地址和 CIDR 前缀描述目标所在的地址块；路由器用最长前缀匹配选出下一跳；设备再用ARP 找到当前链路上下一跳的地址，发出链路帧。你已经能从“数据报里有什么”继续解释到“它为什么从这个出口走、第一帧发给谁”。
