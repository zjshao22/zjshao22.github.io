第二十四节：DNS——名字怎样找到服务

更换服务器后，服务的地址变了，为什么学生收藏的名字还可以继续使用？名字与网络位置分开，使应用可以移动；但全世界的名字也无法只靠一张手工维护的地址表。

本节把 DNS 看成一个按名字层次划分责任、通过查询取得记录的分布式数据库。获得地址以后，连接、路由、TLS 和 HTTP 仍各自需要完成工作。

一、从一张地址表到分布式委派

朴素办法是每台电脑存一份“名字 → IP”文件。小型实验中它能工作，规模变大后就出现三个问题：谁负责修改、如何同步所有副本、单台维护服务器出故障怎么办？

DNS 使用有层次的名字。例如 notes.study.example. 从右向左属于根、example、study 等层次；末尾的点表示完整名字到达根。这里的 .example 是教学名字，不是学校真实域名。

域是名字树的一部分，区域（zone）是某组权威服务器实际负责的数据范围。一个域可以把子域委派出去，因此“域名后缀相同”不意味着全部记录由同一台服务器保存。

角色持有什么或做什么不应误解成什么
本机存根解析器代表应用发起查询不一定自己遍历根服务器
递归解析器帮客户端取得最终结果，并缓存不拥有全世界所有域名的权威数据
根服务器提供顶级域的委派信息不保存每个网站的 IP
顶级域权威服务器提供下一级区域的委派不负责把网页传回浏览器
某区域的权威服务器对自己的区域提供权威记录不一定接受陌生客户端的递归请求

同一个服务可以有多个权威服务器；它们提供冗余。客户端配置的解析器可能来自校园网络、运营商，或浏览器的加密 DNS 设置，不能仅凭“浏览器访问了网站”断言用了哪一个。

二、递归与迭代是两种查询关系

递归请求表达“请给我最后的答案或失败结果”；迭代查询允许服务器回答“我不知道最终值，但下一步可以问谁”。常见情况是电脑向递归解析器提问，解析器再通过迭代查询走完委派链。

应用请求 notes.study.example 的 A 记录
本机或解析器的缓存可能使后续步骤省略。
本机向配置的解析器请求结果
解析器询问根服务器
这是教学名字空间的假设，不是真实互联网查询记录。
收到 example 的委派信息
解析器询问 example 的权威服务器
收到 study.example 的委派信息
解析器询问 study.example 的权威服务器
得到地址记录与 TTL
解析器缓存结果并回复电脑
电脑随后才能选择地址并尝试连接服务。

上述流程是空缓存下的简化模型。如果已有可用的父区域委派或目标记录，解析器不必每次从根开始。委派响应中的 NS 记录说明该问哪些名字服务器；必要的 glue 地址帮助解析器到达它们，但不能把所有附加记录都当成同等可信的最终答案。

DNS 常用 UDP 53，也使用 TCP 53；响应截断等情况可能促使客户端改用 TCP。不能背成“DNS 永远用 UDP”。传输成功也不证明回答正确，仍须检查名字、类型、状态及验证策略。

三、同一个名字可以有不同类型的答案

DNS 的查询单位包含名字和类型。查不到 A 记录，并不一定表示这个名字不存在：它可能只有 AAAA 或其他记录。

类型内容用途或注意点
AIPv4 地址为 IPv4 连接提供候选位置
AAAAIPv6 地址为 IPv6 连接提供候选位置
CNAME另一个规范名字还须继续解析目标名字；常规 CNAME 所在名字不能同时随意放其他数据
NS区域的名字服务器表达权威服务或委派关系
MX邮件交换服务器及优先级值是主机名，需要进一步取得地址；较小优先级值优先
PTR地址对应的名字用于反向查询，不保证与正向记录互为唯一对应
TXT文本数据常承载验证和邮件策略信息，并非网页正文
SOA区域管理参数包括区域版本等信息，也参与负缓存时间的确定
SRV某服务的目标、端口及选择参数应用必须支持它，不能假定浏览器对所有 URL 都查 SRV

一个名字可返回多个地址。客户端如何选择、是否尝试 IPv6、何时改用另一个地址，由客户端算法与网络条件共同决定；DNS 回答的第一行不一定是实际连接地址。

NXDOMAIN表示名字不存在；NOERROR 且缺少所问类型的答案可能是名字存在但该类型无数据；SERVFAIL表示解析未能完成，例如上游失败或验证失败。三者支持的诊断结论不同。

四、TTL 解决效率，也带来更新延迟

记录的 TTL 是允许缓存使用的时间上限，通常以秒计。缓存命中可减少查询数量和等待时间，但权威服务器更新记录不会把所有已有缓存瞬间清空。

以下是教学构造：解析器在 t = 0 s 收到 notes.study.example A 192.0.2.10，TTL 为 120 s；在 t = 40 s，权威服务器把它改成 192.0.2.20。忽略其他缓存、预取和特殊过期服务策略。

查询时刻解析器可以怎样回答剩余 TTL 或原因
30 s缓存中的 192.0.2.1090 s
80 s缓存中的 192.0.2.1040 s；尚不需要知道权威已更新
121 s重新查询后得到 192.0.2.20新结果按其新 TTL 开始计时

因此“我已经在服务器改了地址，你的查询还是旧的”不自动证明解析器坏了。计划迁移时，提前降低 TTL 才能让之后取得记录的缓存更早过期；在迁移一刻降低 TTL，不能追回先前按旧 TTL 缓存的记录。

负缓存也会缓存“名字不存在”或“某类型无数据”的结果。其时间受权威响应中的 SOA 参数等约束，不是永远保存失败。若在刚收到否定回答后创建了名字，其他客户端仍可能暂时取得缓存的否定结果。负缓存规范说明了这类回答的处理。

权威记录在第 40 秒更新，解析器原记录 TTL 120 秒；第 80 秒返回旧地址，最合理的解释是什么？

五、DNSSEC 与加密 DNS 保护不同环节

DNSSEC 用签名及信任链帮助验证记录的来源和完整性，包含对不存在情况的认证；它不隐藏查询名字。验证需要可信锚点和正确的验证过程，单看响应里有签名记录不能宣称已验证成功。DNSSEC 的能力与边界

DNS over HTTPS（DoH）把 DNS 消息放在 HTTPS 中传送，保护客户端到该解析器这一段通道；解析器仍能知道查询内容。DoH 不等于网站本身的 HTTPS，也不自动使所有权威数据带上 DNSSEC 签名。DoH 规范

可以把它们分成两个检查：回答是否能被验证，以及查询途中谁能读到内容。它们可以结合使用。无论哪一种，都不能保证得到的服务一定诚实、应用一定没有漏洞。

七、独立推演与迁移

一个教学解析器在 t = 10 s 缓存 image.study.example CNAME edge.study.example，TTL 60 s；同时缓存 edge.study.example A 192.0.2.30，TTL 20 s。假定无其他缓存、两条记录独立过期。

请解释 t = 25 s 与 t = 35 s 的查询分别需要哪些新查询。不要先展开答案。

第一层提示：把每条记录的过期时刻单独列出

CNAME 的过期时刻是取得时刻加 60；A 的过期时刻是取得时刻加 20。不能用较长的 TTL 替另一条记录延寿。

第二层提示：名字别名与目标地址是两步

只要 CNAME 仍可用，就还知道应解析哪个名字；但如果 A 已过期，仍须取得该名字的新地址记录。

核对完整推演

CNAME 到 70 s 过期，A 到 30 s 过期。25 s 时两者都有效，可使用缓存。35 s 时别名关系仍有效，目标地址需要重新查询；不必因为地址过期就从头遗忘整个委派树。

最后换一个情境独立回答：刚创建一个名字，有人持续看到 NXDOMAIN，有人已能访问；还可能存在哪些不同缓存位置？应收集哪些查询状态、TTL 和解析器信息？如果 DNS 已返回地址而连接超时，下一步为什么不应继续只改 DNS？

完成标志是能区分名字不存在、类型无数据、解析失败、连接失败和 HTTP 错误，并用观察支持自己的判断。DNS 的名字层次与委派基础可查阅DNS 概念规范。
