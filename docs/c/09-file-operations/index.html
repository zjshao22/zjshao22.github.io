文件操作与数据持久化

在之前编写的所有程序中，变量和数组均存放在计算机的随机存取内存（RAM）中。一旦程序执行完毕退出，或者电脑关机断电，内存中的数据就会彻底灰飞烟灭。

为了将计算结果、学生档案或用户日志长久保存下来，我们必须将数据写入外存磁盘中——这就是文件（File）操作与数据持久化。

本节深入解析文本文件与二进制文件的底层差异、FILE 文件指针结构、fopen 打开模式权限规范以及字符、字符串、格式化与数据块级读写操作。

二、文件指针 FILE* 与 fopen() 打开模式

1. 文件指针：FILE *fp

C 标准库在 <stdio.h> 中预定义了一个名为 FILE 的结构体类型。它记录了被操作文件的缓冲区地址、读写当前位置、打开模式和状态标志等信息。 操作文件时，我们始终通过指向该结构体的指针变量（FILE *fp;）来与文件流进行交互。

2. 文件打开函数：fopen()

  • filename：要打开的文件路径及文件名（如 "data.txt"）。
  • mode：打开模式字符串（注意必须为双引号字符串）。
  • 返回值：若打开成功，返回指向该文件的有效 FILE* 指针；若打开失败，返回 NULL（空指针）！

3. 核心打开模式深度辨析

模式字符串含义文件已存在时的行为文件不存在时的行为
"r"只读 (Read) 打开文本文件正常打开，光标位于文件开头出错返回 NULL ❌
"w"只写 (Write) 打开文本文件强行清空并销毁原有全部内容！新建一个空文件 ✔
"a"追加 (Append) 打开文本文件保留原有内容，光标位于文件末尾新建一个空文件 ✔
"rb" / "wb" / "ab"二进制方式打开规则与上述对应模式完全相同，仅以二进制流处理—
"r+" / "w+" / "a+"读写模式打开允许同时进行读和写操作规则同基准模式

极高频关键陷阱

  1. 用 "r" 读取文件前，必须做非空校验：若文件不存在，fopen 会返回 NULL，此时直接操作野指针会导致程序崩溃！ 2. 用 "w" 打开已存在的文件，会无情抹掉原文件所有内容！如果想在原文件后面续写，必须使用追加模式 "a"！

三、文件关闭规范：fclose()

文件操作完毕后，必须显式调用 fclose() 关闭文件：

为什么必须及时关闭文件？

  1. 刷新 C 流缓冲区（Flush）：为了提升 I/O 效率，C 标准库对文件流提供了内存缓冲。调用 fclose() 会将 C 运行时流缓冲区中积攒的全部数据刷入操作系统内核并关闭流。规范程序应检查 fclose() 返回值（成功返回 0，失败返回 EOF）。
  2. 释放操作系统资源：操作系统对单个进程同时打开的文件描述符有数量限制，及时关闭可避免句柄泄漏。

  • ptr：内存缓冲区的首地址。

本节小结与核心要点

  1. 流式文件特征：C 语言以连续字节流的形式组织文件。
  2. 两类文件本质：文本文件按字符编码存储；二进制文件按字节序列存储。
  3. fopen 返回值：成功返回 FILE*，失败返回 NULL。
  4. 模式特性："r" 不存在报错；"w" 存在清空；"a" 末尾追加。
  5. fclose 规范：冲刷 C 流缓冲区数据并释放文件描述符，检查返回值确保无 I/O 错误。
