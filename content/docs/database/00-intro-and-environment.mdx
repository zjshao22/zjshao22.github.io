# 数据库概念与环境准备

在开发校园选课系统、教务管理系统或各类现代软件时，文件存储（如 Excel、CSV 或文本文件）很快就会遇到并发冲突、数据冗余、查询缓慢和安全性缺失等瓶颈。**数据库系统（DBS）** 就是为了解决大规模数据的持久化存储、高效检索与并发安全而诞生的核心基础设施。

本节重点帮助你建立数据库整体心智模型，掌握客户端与服务器的区别，理解三级模式与数据独立性，并搭建好实践所需的 MySQL 与 Workbench 环境。

## 一、核心概念辨析：DB、DBMS、DBS 与 DBA

在数据库技术中，有四个经常被混淆的基础术语：

| 缩写     | 全称                                         | 含义与定位                                                              | 本课程对应实例                                     |
| -------- | -------------------------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------- |
| **DB**   | Database（数据库）                           | 长期存储在计算机内、有组织的、可共享的大量数据的集合                    | 本课程中的 `teachingdb_***` 数据库文件             |
| **DBMS** | Database Management System（数据库管理系统） | 位于用户与操作系统之间的一层数据管理核心系统软件                        | 电脑上运行的 **MySQL 8.x 服务进程**                |
| **DBS**  | Database System（数据库系统）                | 引入数据库技术后的整个计算机系统，由 DB、DBMS、应用系统、硬件和人员构成 | 包含 MySQL、教务库、Workbench 与师生的完整运行环境 |
| **DBA**  | Database Administrator（数据库管理员）       | 负责全面规划、设计、维护与安全授权数据库的专门技术人员                  | 实验三中负责备份恢复与账户授权的角色               |

## 二、客户端与服务器（Client / Server）架构

许多初学者容易把 **MySQL Workbench**当成数据库本身。必须清楚区分**客户端（Client）**与**服务器（Server）**：

<ClientServerArchitectureFigure />

1. **MySQL Server（`mysqld`）**：在后台常驻运行的服务进程。它独占监听网络端口（默认**3306**），真正负责解析 SQL、优化查询计划、读写磁盘文件并维护事务。
2. **客户端工具**：
   - **MySQL Workbench**：图形化管理工具，提供可视化的建表表单、ER 模型图与 SQL 查询编辑器。
   - **系统终端命令行 `mysql`**：轻量级控制台工具，用于快速排查、脚本批量执行与管理恢复。
   - **外部应用程序**：在实验四中编写的 Python/Node.js/Java 程序，通过数据库驱动连接 MySQL 执行业务操作。
3. **关键准则**：客户端无论被关闭、崩溃或重启，都不会丢失数据库中已提交的数据；但如果服务端 `mysqld` 未启动，任何客户端都将无法连接（提示 Connection refused 或 Can't connect to MySQL server）。

## 三、三级模式结构与两级映像

为了实现数据的高度独立性，ANSI/SPARC 提出了著名的数据库三级模式体系：

<ThreeSchemaFigure />

### 1. 三级模式定义

- **外模式（External Schema，也称子模式或用户模式）**：
  - 用户或应用程序能够看见和使用的局部数据的逻辑结构和特征描述。
  - 一个数据库可以有**多个外模式**（例如不同角色的视图、不同接口所需的数据子集）。
- **模式（Schema，也称概念模式或逻辑模式）**：
  - 数据库中**全体数据**的逻辑结构和特征的完整描述，是所有用户的公共数据视图。
  - 一个数据库**只有一个模式**。四张基准表（`t_student`、`t_teacher` 等）的字段、数据类型及主外键约束即构成本数据库的模式。
- **内模式（Internal Schema，也称存储模式或物理模式）**：
  - 数据在物理存储介质上的存储方式和物理结构描述（如文件的组织方式、B+树索引、数据是否压缩、存储路径等）。
  - 一个数据库**只有一个内模式**。

### 2. 两级映像与数据独立性

- **外模式 / 模式映像（保证逻辑数据独立性）**：
  - 当概念模式发生改变（如增加新列、修改非主键约束）时，DBA 只需要调整外模式/模式映像（例如修改视图定义），而**无需修改已有的应用程序**。
- **模式 / 内模式映像（保证物理数据独立性）**：
  - 当物理存储结构发生改变（如更换更高性能的磁盘存储格式、新建索引、改变存储引擎）时，只需要修改模式/内模式映像，而**概念模式和上层应用程序无需改动**。

## 四、MySQL 环境准备与实操验证

### 1. 登录与验证执行位置

在日常实验与机考准备中，必须清晰区分**系统终端命令行（Shell / Terminal）**与**MySQL SQL 编辑器**的执行边界：

```bash
# 【系统终端命令行】启动登录客户端
mysql -u root -p
# 输入密码后进入 mysql 交互提示符：mysql>
```

在系统终端执行操作系统指令（如 `mysqldump`、`cd`、`ls`）；而在 `mysql>` 提示符下或 Workbench SQL 编辑器中，只能执行 SQL 语句！

### 2. 建立个人实验数据库

实验一要求建立名为 `teachingdb_***` 的个人数据库，其中 `***` 为学生姓名拼音缩写（例如学生张三的库名为 `teachingdb_zs`）：

```sql
-- 1. 查看当前 MySQL 实例中已存在的所有数据库
SHOW DATABASES;

-- 2. 创建个人教学数据库，指定字符集为 utf8mb4，排序规则为 utf8mb4_0900_ai_ci
CREATE DATABASE IF NOT EXISTS teachingdb_chen
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

-- 3. 切换当前会话所使用的工作数据库（至关重要！）
USE teachingdb_chen;

-- 4. 验证当前所在数据库名称
SELECT DATABASE();

-- 5. 查看当前库下的所有表（新建库此时为空集）
SHOW TABLES;
```

<Callout type="warn" title="排错关键点：先选库再执行">
  很多初学者执行建表或查询时遇到错误 `ERROR 1046 (3D000): No database
  selected`，原因就是忘记先执行 `USE teachingdb_***;`。在 Workbench
  中，也可以在左侧 SCHEMAS 面板双击该库名，让其变为粗体加粗状态。

</Callout>
